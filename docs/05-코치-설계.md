# 05 · 코치

계약만 적는다 — **데이터 형식 · 라벨 값 · 인터페이스**. 측정 기록은 넣지 않는다.
데이터는 다시 만든다.

---

## 1. 목적

```
[미션 추천]  → POST /v1/coach/runs      → 주간 1개 + 일일 N개를 편성한다
[코치 대화]  → POST /v1/coach/messages  → 물음에 답한다
```

카드 한 장은 **운동명 + 영상 토막 + 문구 + 근거**다.

---

## 2. 만들 것 셋

```
처방문 ──→ ① 운동 표 ──┐
                       ├──→ ③ 미션 집합 ──→ 편성
화면 글자 ─→ ② 영상 토막 ┘
```

①②는 ③을 만들기 위한 것이다. **③ 하나가 추천의 검색 대상이다** — 요청마다 처방
칸에서 조립하지 않는다.

### ① 운동 표 — `exercises.csv`

미션을 대표하는 **고유한 운동 이름** 하나가 한 행이다.

| 열 | 형 | 무엇 |
|---|---|---|
| `exercise_id` | str | 미션의 키. 이름에서 만든다 (공백·가운뎃점 제거) |
| `exercise_name` | str | 대표 표기 |
| `raw_forms` | str | 합친 원문. `;` |
| `merge_reason` | str | 왜 합쳤나. 합치지 않았으면 빈칸 |
| `kind` | `낱개`·`묶음` | 묶음은 운동 하나를 가리키지 못한다 |
| `blocked_with` | str | 합치려다 막힌 상대. `;` |
| `phase_share` | str | `준비운동:0.301;본운동:0.699` |
| `prescribed` | int | 처방 횟수 |
| `age_groups` | str | 처방된 연령대. `;` |
| `indoor` | `안`·`밖`·빈칸 | 근거가 없으면 비운다 |

**합치는 근거는 「같은 처방 칸에 함께 나오지 않는다」다.** 한 칸에 나란히 처방된 두
이름은 별개 운동이다 — 이름이 얼마나 닮았는지는 근거가 아니다. 반대 방향(함께 안 나오면
같다)은 쓸 수 없다.

합치지 않은 후보도 `blocked_with` 에 남긴다. 기록이 없으면 같은 후보가 다시 올라온다.

### ② 영상 토막 — `video_segments.csv`

**`video_id` 는 유튜브 영상 한 편이 아니라 그 안의 한 토막이다.** 한 영상에 운동이
여럿이라 주소는 `url` 하나가 아니라 **`url` + `start_sec` + `end_sec`** 다.

| 열 | 형 | 무엇 |
|---|---|---|
| `video_id` | str | 유튜브 id |
| `start_sec` · `end_sec` | int | 토막. **키는 `video_id`·`start_sec`** |
| `label_end_sec` · `gap_sec` | int | 이름표가 사라진 시각과 그 차이 |
| `last` | bool | 영상의 마지막 토막인가 |
| `duration_sec` | int | `end_sec - start_sec` |
| `length_basis` | `next_start`·`label_end` | 길이를 무엇으로 쟀나 |
| `exercise_name` | str | ①의 이름 |
| `age_group` | 연령대 | 영상의 연령 라벨 |
| `source` | `screen`·`screen_bar`·`title` | 어디서 읽었나 |
| `common` | bool | 공통 준비·마무리인가 |
| `evidence_text` · `chunk_id` · `citation_label` | str | 인용에 실을 값 |
| `url` | str | 딸린 값이다. 키가 아니다 |

**길이는 이름표 끝이 아니라 시작 시각 사이로 잰다** — 이름표는 동작 중에도 사라진다.
`gap_sec` 이 크면 길이를 쓰지 않는다.

### ③ 미션 집합 — `missions.csv`

```
미션 = 운동 1개 × 영상 토막 0~1개 × 라벨
```

카드 한 장이 이 표의 한 행이다. **한 운동에 토막이 여럿이면 토막마다 한 미션이다.**

| 열 | 형 | 무엇 |
|---|---|---|
| `mission_id` | str | `{exercise_id}@{video_id}#{start_sec}`. 영상이 없으면 뒤를 비운다 |
| `exercise_id` · `exercise_name` | str | → ① |
| `video_id` · `start_sec` · `end_sec` · `url` | str·int | → ② (한 토막) |
| `video_age_group` | 연령대 | **영상의 연령 라벨.** 비면 아이에게 나가지 않는다 |
| `targets` | str | 대상 라벨 `연령대-성별`. `;` |
| `phase` | 단계 | ①·② 에서 |
| `common` | bool | → ② |
| `best_rank` · `prescribed` | int | 처방 순위와 횟수. **둘은 다른 값이다** |
| `cell_chunk_id` · `cell_citation_label` | str | 정보용. **인용으로 쓰지 않는다** |
| `video_chunk_id` · `video_citation_label` | str | 영상 인용 |

**값을 복사해 넣지 않는다.** 운동 이름과 토막은 ①②가 정본이고 이 표는 잇는 자리다.
두 번 돌려도 같은 표가 난다 — `mission_id` 에 해시를 쓰지 않는다.

**영상이 없는 미션은 서비스에 내보내지 않는다.** CSV 는 개발 중 비어 있어도 되지만,
응답의 `video` 가 `null` 이면 **결함이다** — 백엔드도 프론트도 받지 않는다.

### 세우는 데 쓰는 것

| 파일 | 무엇 |
|---|---|
| `prescription_cells.csv` | 처방 칸 = (연령대 × 나이 × 성별 × 단계). ③의 `targets`·`best_rank`·인용이 여기서 온다 |
| `exercise_vocabulary.csv` | 처방문에서 뽑은 원어휘. ①의 입력 |
| `chunks.csv` + `data/index/` | 대화가 검색하는 코퍼스 |
| `video_labels.csv` · `.sql` | 백엔드 적재 형식 (영상 1편 = 1행) |
| `medical_terms.csv` · `medical_queries.csv` | 의료 어휘 차단 |

## 3. 라벨 값

**①②③ 의 칸에 들어가는 값이다. 여기 없는 값을 쓰지 않는다.**

| 라벨 | 어느 표 | 값 |
|---|---|---|
| `age_group` · `video_age_group` | ②③ | `유아기` `유소년` `청소년` `성인` `어르신` |
| `sex` | ③ (`targets` 의 뒷자리) | `M` `F` |
| `phase` | ①②③ | `준비운동` `본운동` `정리운동` |
| `kind` | ① | `낱개` `묶음` |
| `indoor` | ① | `안` `밖` · 빈칸 |
| `source` | ② | `screen` `screen_bar` `title` |
| `length_basis` | ② | `next_start` `label_end` |
| `common` · `last` | ②③ | `True` `False` |

처방 칸 표에는 `age_unit` (`세`·`개월`)이 하나 더 있다 — **유아기만 개월이다.**

연령대 → 만 나이 폭. **백엔드와 같은 값을 쓴다** — 두 벌이 되면 우리 라벨이 그쪽
필터를 통과하지 못한다.

| 연령대 | 만 나이 |
|---|---|
| 유아기 | 0~6 |
| 유소년 | 7~12 |
| 청소년 | 13~18 |
| 성인 | 19~64 |
| 어르신 | 65~120 |

백엔드 `exercise_videos` 의 코드값 — `intensity` `LOW` `MID`, `space` `SMALL_ROOM`,
`noise` `QUIET` `NORMAL`. **잰 값이 없으면 `NULL` 이다. 더미로 채우지 않는다.**

## 4. 인터페이스

필드는 `docs/03` 이 정본이다. 여기는 **백엔드 구현이 실제로 어떻게 움직이는지**만 적는다.

### 4.1 부르는 방식

| | `coach/runs` | `coach/messages` |
|---|---|---|
| `POST` 예산 | 2초 · 재시도 없음. 응답에서 `run_id` 만 쓴다 | 10초 |
| 폴링 | `GET` 을 1.5초 간격 최대 40회, 호출마다 3초 | 없음 |
| 그래서 | **한 run 을 1분 안에 끝낸다** | **한 답을 10초 안에 낸다** |

- **`409` 를 내지 않는다.** 중복은 백엔드가 가족·주 단위로 막는다.
- **`poll_after_ms` 는 버려진다.** 간격은 백엔드 설정값 고정이다.
- 입력은 **가족 전원**이다 — `응원` 과 만 4세 미만도 온다. 측정값이 없으면
  `measurements` 가 빈 객체가 아니라 **`null`** 이다.
- **`profile_refs` 에 상한을 두지 않는다.** 계약은 1~4명이지만 백엔드는 가족 전원을
  보낸다. 닫으면 `422` 가 나고 그것은 `503` 으로 번역되지 않아 run 이 실패한다.

**요청에 실려 오는 값** — 이것은 미션의 라벨이 아니라 백엔드가 보내는 것이다.

| 필드 | 아는 값 | 모르는 값이 오면 |
|---|---|---|
| `role` | `주행자` `동반자` `응원` | **닫지 않는다.** 편성은 `주행자`·`동반자` 만 보고 나머지는 빠진다 |
| `input_level` | `L0` `L1` `L2` | 닫지 않는다. 편성이 보지 않는다 |
| `age_unit` | `세` `개월` | 닫지 않는다 |

**`Literal` 로 닫지 않는 이유** — 값이 하나 늘면 `422` 가 나고, 그것은 `503` 으로
번역되지 않아 run 이 실패한다. 아는 값만 적어 두고 모르는 값은 흘린다.

### 4.2 자르는 한도

| 우리가 내는 것 | 한도 |
|---|---|
| `run_id` | 40자 |
| `refusal_reason` (runs) | 60자 |
| `refusal_reason` (messages) | 40자 |
| `missions[].title` | 120자 — 「오늘 · 」 같은 접두어를 붙이지 않는다 |
| `copy.child` · `copy.parent` | 400자 |
| `citations[].chunk_id` | 200자 |

### 4.3 터지는 자리

1. **`citations[].label` 을 빼거나 `null` 로 내면 역직렬화가 터진다.** 그 예외는
  `503` 으로 번역되지 않고 대체 편성도 타지 않는다 — run 이 실패로 끝난다.
  → **인용 세 필드(`index`·`label`·`chunk_id`)를 언제나 함께 낸다.**
2. **`sessions[].evidence` 가 비면 근거가 좁아지지 않고 넓어진다** — 빈 배열이면 그
  실행의 인용 전체가 그 미션에 붙는다. 오류가 나지 않고 응답으로도 알 수 없다.
  → 최소 1개.
3. **`sessions[].video.video_id` 가 백엔드 카탈로그에 없으면 영상 전체가 버려진다.**

`sessions[].duration_min` 은 낱개가 아니라 **합계**가 진행도 목표값이다.
`participants[].ref` 가 가족에 없으면 그 참여자만 빠진다.

### 4.4 백엔드 구현과 어긋난 것

**백엔드 구현을 따른다.** `docs/03` 과 다르면 백엔드가 보내고 읽는 모양에 맞춘다.

| 무엇이 다른가 | 우리가 쓰는 값 |
|---|---|
| **`sessions[].video` 에 `end_sec` 자리가 없다** | 보내지 않는다. 토막 끝은 ②에만 있다 |
| **구간별 라벨을 둘 자리가 없다** — 영상 1편 = 1행, 미션 1개에 영상 1개 | 미션 1개에 토막 1개 |
| `sessions[].fitness_factor` 가 어느 컬럼에도 저장되지 않는다 | 실측 라벨이 있으면 그 값, 없으면 빈 문자열 |
| `exercise_name` 이 한 문자열로 접혀 저장되고 프론트 응답에 그 필드가 없다 | 계약대로 세션마다 낸다. 제목에 욱여넣지 않는다 |
| `copy.child` 가 저장만 되고 화면에 안 나간다 | 둘 다 낸다 |
| **운영의 영상 카탈로그가 비어 있다** | 계약대로 낸다. 붙지 않는 것은 우리 결함이 아니다 |
| 미션 목록에 날짜 필터가 없다 | 참여자마다 미션 1개. 하루 미션을 여러 개 만들지 않는다 |
| 측정 항목 코드 집합이 좁고, 없는 코드는 오류다 | 요청에 온 열로만 판정한다 |
| 체력 점수를 저장할 컬럼이 없다 | **답 대기.** 등급은 백엔드 정의를 따른다 |
| 영상 라벨을 넣을 경로가 없다 | 적재 SQL 을 파일로 낸다. 넣는 것은 백엔드 담당이 한다 |

**벡터 저장소는 우리 결정이다** — 스키마·모델·차원에 외부 제약이 없다. 대가로 연령
안전과 `chunk_id` 결정성이 홀로 선다. 우리가 깨면 아무도 못 잡는다.

## 5. 코치가 도는 순서

### 5.1 미션 추천

```
① resolve   프로필 → 연령대·처방 칸. 칸이 없으면 같은 성별의 가장 가까운 나이로 당긴다
② retrieve  ③에서 targets 로 좁히고, 그 사람의 칸 청크에 있는 이름만 남긴다
③ plan      정렬 → 고르기 → 일일·주간 배분 → 문구
④ verify    인용·문구·연령을 검사한다. 걸리면 강등하거나 거부한다
```

**고르는 값은 처방 빈도 하나다** — 그 사람의 또래 처방에 많이 나온 순서다. 흔한 방식을
먼저 쓴다. 다른 지표가 낫다는 측정이 있을 때만 바꾼다.

**정렬 순서 — 영상 있음 → 공통 아님 → 본운동 → 처방 순위.**
영상이 첫 축인 이유: 영상 붙은 후보는 연령대마다 손에 꼽는다. 단계를 앞세우면 준비·정리
운동의 영상 붙은 후보가 영상 없는 본운동에 밀린다.

같은 주에는 같은 편성, 다음 주에는 다른 편성이다 (주차로 회전).
**회전은 같은 순위 묶음 안에서만 한다** — 묶음을 넘어 돌리면 우선순위가 뒤집힌다.

**칸이 없을 때**

| 상황 | 무엇을 하나 |
|---|---|
| 그 나이 칸이 없다 | 같은 성별의 가장 가까운 나이로 당긴다. 당김을 응답에 남긴다 |
| 그 성별 칸이 없다 | **넓히지 않는다** — 「또래 여아 처방」이라는 인용이 거짓이 된다 |
| 나이가 칸 범위 밖이다 | 빈 결과다. 예외를 던지지 않고 인용 0 으로 거부한다 |

### 5.2 코치 대화

```
① embed    물음을 임베딩한다
② search   연령 필터를 걸고 검색한다. 임계값 아래는 버린다
③ write    찾은 근거로 답을 쓴다. 실패하면 발췌로 강등한다
④ verify   본문의 [n] 이 인용 범위 안인가. 밖이면 응답 전체를 거부로 바꾼다
```

- **연령 필터는 검색의 `WHERE` 절에 있고 정렬 뒤 후처리가 아니다.** 끄는 인자를 만들지
  않는다 — 인자가 있으면 언젠가 꺼진다.
- **나이·성별은 검색이 아니라 필터로 좁힌다.** 처방 청크는 서로 닮아서 문장 유사도로
  갈리지 않는다.
- **관련성은 임계값이 정한다. LLM 에게 맡기지 않는다** — 근거가 물음에 못 미친다는
  모델의 말은 거부가 아니라 발췌 강등이다.
- **답을 편집해서 통과시키지 않는다.** 인용 번호가 범위 밖이면 번호를 지우는 것이
  아니라 응답 전체를 거부로 바꾼다.
- **거부에도 출처를 남긴다** — 검색이 못 찾은 것과 모델이 못 쓴 것이 구분되지 않으면
  임계값을 고칠지 프롬프트를 고칠지 알 수 없다.

### 5.3 연령 — 누구에게 어떤 영상을 내보내도 되나

| 프로필 | 내보내도 되는 영상 |
|---|---|
| 아이 (`유아기`·`유소년`·`청소년`) | **같은 연령대만** |
| 만 7~10세 | 아이 연령대 전부 — 예외 (그 구간은 측정도 영상도 비어 있다) |
| 아이 · 연령 미상 영상 | **안 된다** — 다른 것이 아니라 모르는 것이다 |
| 아이 · 성인·어르신 영상 | **안 된다** |
| 성인·어르신 | 같은 연령대 + 연령 미상 |

**이 판단이 곧 서비스의 판단이다** — 백엔드는 우리가 낸 영상을 연령으로 걸러내지 않고
카탈로그에 있는지만 본다.

**못 나가는 영상이면 미션을 버리지 않고 영상만 뗀다.**
**한 영상의 토막들이 여러 연령대면 영상의 연령을 비운다** — 폭을 넓혀 두 연령대를
덮으면 필터가 양쪽에 내보낸다.

### 5.4 근거

**인용은 요청 시점에 그 사람의 칸에서 가져온다.** 미션 표의 `cell_chunk_id` 는 그 운동이
전체에서 가장 앞섰던 칸이라, 그대로 쓰면 요청자와 연령대가 다른 인용이 붙는다.

표가 `targets` 로 통과시켜도 **그 사람의 칸 청크에 이름이 없으면 후보에서 뺀다** — 근거가
그 운동을 말하지 못한다.

### 5.5 일일·주간

**기간으로만 가른다.** 주기를 담는 필드를 만들지 않는다 — 계약·DB·프론트 응답 어디에도
없고, 프론트가 날짜로 가를 수 있다.

| | 기간 | 세션 |
|---|---|---|
| 일일 | `start_date == end_date` | 1개 · `day_offset` 은 `0` |
| 주간 | `start_date` ~ `+6일` | `days_per_week` 개 · `day_offset = i × 7 ÷ days_per_week` |

아이(`주행자`)는 **일일 `days_per_week` 개 + 주간 1개**, `동반자` 는 자기 연령대 칸에서
뽑은 **주간 1개**. `응원` 은 편성에서 빠지고 참여자에도 넣지 않는다.

**주간 미션은 그 주 일일 미션의 합이다.** 운동을 다르게 두면 아이가 일일 세 개만 해도
주간이 완료로 뜬다 — 진행도가 기간 안 활동 합계이기 때문이다. 같은 운동·같은 토막을
담으면 「일일을 다 하면 주간도 된다」가 참이 된다.

> **카드의 분을 더하면 실제의 두 배다.** 일일 3×15분과 주간 45분이 같은 45분을 가리킨다.
> 프론트는 카드의 목표값을 합산하지 않아야 한다.

### 5.6 문구

운동을 고른 뒤 그 운동과 근거를 프롬프트에 넣어 문구를 받는다.
**LLM 이 쓴 문구도 검사를 통과해야 나간다.** 하나라도 걸리면 **규칙 문구로 강등**한다
(거부가 아니다).

| 검사 | 왜 |
|---|---|
| 금지 어휘 없음 (`부족`·`미달`·`하위` 등) | 아이가 읽는다 |
| 주당 횟수가 맞나 | 없는 횟수를 지어낸다 |
| `child`·`parent` 두 줄이 다 있나 | 하나만 오면 카드가 빈다 |

- **그 운동이 무엇을 기른다고 말하지 않는다.** 요인을 재지 않았다 — 말할 수 있는 것은
  「또래 처방에 이만큼 나왔다」뿐이다.
- **아이가 참여하지 않는 미션의 `copy.child` 는 비운다.**
- **LLM 은 기본으로 꺼져 있다.** 꺼지면 발췌로 답하고 외부 호출이 0 이다.
  **켜져 있는데 키가 없으면 첫 호출에서 오류를 낸다** — 조용히 발췌로 가면 운영자는
  LLM 이 도는 줄 안다.
- 쓰기는 환경변수로 바꿔 끼운다. **프롬프트는 두 백엔드가 같은 것을 쓴다** — 갈리면
  한쪽만 인용 검사를 통과한다.

## 6. 할 일

| | 무엇 | 상태 |
|---|---|---|
| ① | 운동 표를 만든다 — 미션을 대표하는 고유 이름 | **났다** (`make exercises`) |
| ② | 화면을 떠서 토막으로 가르고 ①의 이름에 맞춘다 | 길은 돈다. 성인·어르신 토막이 없다 |
| ③ | 미션 집합을 내고 **검색(임베딩)을 붙인다** | 표는 있다. **미션이 색인에 없다** |
| ④ | LLM 을 붙여 두 문을 끝낸다 | 두 경로 모두 돈다 |

③의 남은 것 둘.

- **미션을 임베딩한다.** 지금 미션을 찾는 방식은 `targets` 정확 일치 필터 하나다.
  색인에는 청크만 있다.
- **칸당 운동 수 상한을 다시 본다.** 그 상한은 청크의 토큰 한도 때문인데, 미션 집합은
  청크가 아니라 표의 행이라 같은 한도가 걸릴 이유가 없다. 지금은 상한 밖의 운동에
  미션이 하나도 없다.

## 7. 채우지 못한 것

**더미로 메우지 않는다.** 없으면 없다고 낸다.

| 무엇 | 왜 없나 |
|---|---|
| **영상 null 을 막는 곳** | 규칙은 정해졌는데(영상 없는 미션은 내보내지 않는다) 코드에 그 관문이 없다. 성인·어르신은 붙을 영상이 0개라 **막는 것과 영상을 늘리는 것을 함께 해야 한다** |
| 미션의 임베딩·검색 | 할 일 ③ 이 남아 있다 |
| `targets` 의 항목·등급 축 | 처방 칸 표에 항목·등급이 없다. 지금은 `연령대-성별` 까지다 |
| `intensity` | 토막 길이가 근거인데 마지막 토막의 길이를 믿을 수 없다 |
| `indoor` | 판정 규칙이 없다 |
| `fitness_factor` | 처방에서 역산한 요인이 상식 검사를 통과하지 못했다. 실측된 영상 라벨에만 채운다 |
| `space` · `noise` · `equipment` | 잰 값이 없다 |
| `/readyz` 의 벡터 저장소 확인 | DB 드라이버를 넣지 않았다 |
| run 상태 저장 위치 | **프로세스 메모리는 태스크 둘에서 깨진다** |
| 대화 문맥 | 받지 않는다 |

## 8. 미결

**여기 걸린 항목을 임의로 확정하지 않는다.** 기본값으로 진행하되, 그 선택에 의존하는
코드를 쓰기 전에 알린다. 해소되면 **행만 지우고 번호는 비워 둔다.**

| # | 무엇 | 확정 전 기본값 |
|---|---|---|
| ① | `docs/03` 을 어디까지 고칠 것인가 — 합의 대기 | 고치지 않는다 |
| ② | 구간별 라벨을 받을 자리 | 없음 — **확정 전에는 미션 산출 형식을 닫지 않는다** |
| ③ | `sessions[].video` 의 `end_sec` 자리 | 보내지 않는다 |
| ④ | 대화 예산을 넓힐 수 있나 | 지금 예산에 맞춘다 |
| ⑤ | run 상태를 어디에 두나 | 미정 |
| ⑥ | 대상 라벨을 만 나이 폭으로 어떻게 접나 | 대상의 연령대 최소~최대로 편다 |
| ⑦ | 조사만 다른 운동명 — **사람 판단** | 합치지 않는다 |
| ⑧ | 화면 이름이 어휘와 표기만 다를 때 — **사람 판단** | 붙이지 않는다 |
| ⑨ | 운동에 체력요인을 붙이는가 | 빈칸 |
| ⑩ | `space`·`noise` 를 설명문에서 낼 수 있나 | 못 내면 `null` |
| ⑪ | 라벨러 모델과 프롬프트 버전 | 로컬은 `llama`, 배포는 API |
| ⑫ | 대화 문맥을 받는가 | 받지 않는다 |
| ⑬ | 벡터 저장소 확인 대상 | 한 표에 `SELECT 1` 하나만 본다 |
| ⑭ | 묶음 이름을 미션으로 내보내는가 | 버리지 않고 순위를 낮춘다 |
