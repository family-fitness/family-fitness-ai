# 01 · 기술 스택

AI 파트의 런타임과 배포 형상. **무엇으로 만드는가**를 확정한다.
호출 계약은 `03-인터페이스-명세.md`, 데이터 취급은 `02-공공데이터-관리-규약.md`.

---

## 1. 스택

| 계층 | 선택 | 비고 |
|---|---|---|
| 언어 | Python 3.11 | |
| 웹 | FastAPI · uvicorn | 내부망 전용 서비스 |
| 오케스트레이션 | LangGraph | 미션 편성 그래프 1개 |
| 통계·모델 | pandas · numpy · scikit-learn · statsmodels | 분위수 산출, 등급 판정 |
| 검색 | pgvector (기본) / FAISS (로컬·폴백) | 환경변수 하나로 교체 |
| LLM | 외부 API | 편성 문장 생성 1회, 영상 라벨링 |
| 실행 | AWS ECS Fargate | 서비스 + 배치 태스크 |
| 데이터 | RDS PostgreSQL 16 + pgvector · S3 | |
| 모델 관리 | MLflow | `Production` 별칭만 서비스가 로드 |
| CI | GitHub Actions | lint · type · test |

**검색 백엔드를 환경변수로 가른다.** `VECTOR_BACKEND=pgvector|faiss` 하나로 바뀌고
호출부는 같다. DB가 서기 전에도 개발이 멈추지 않게 하려는 것이다.

## 2. 시스템 경계

```
클라이언트 (React Native · Next.js)
        │ HTTPS · 사용자 JWT
   ┌────▼──────────┐
   │ ALB (public)  │
   └────┬──────────┘
        │
 ┌──────▼────────────────────────────────────────────┐
 │ ECS Fargate                                       │
 │                                                   │
 │  api-server ──── JSON ────▶ ai-service            │
 │  Spring Boot 3            FastAPI · LangGraph     │
 │  Java 17 · JWT            (인터넷 인바운드 없음)    │
 │       │                        │                  │
 │       │                   ai-batch (Task)         │
 │       │                   라벨링 · 색인 · 학습      │
 └───────┼────────────────────────┼──────────────────┘
         │                        │
 ┌───────▼────────────────────────▼──────────────────┐
 │ RDS PostgreSQL 16 + pgvector      S3              │
 │  ├ 서비스 테이블 (api-server 소유)   ├ raw/         │
 │  ├ vector_store    (ai-batch 쓰기)  ├ models/      │
 │  └ exercise_videos (ai-batch 쓰기)  └ exports/     │
 └───────────────────────────────────────────────────┘
```

### 2.1 컨테이너를 셋으로 나누는 이유

| 컨테이너 | 성격 | 나눈 이유 |
|---|---|---|
| `api-server` | 상시 · 사용자 요청 | 인가·트랜잭션·승인 게이트의 단일 소유자 |
| `ai-service` | 상시 · 내부 요청만 | LLM 호출은 느리고 실패한다. API 서버 스레드를 그 실패에 묶지 않는다 |
| `ai-batch` | 단발 Task | 라벨링·색인·재학습은 수십 분 돈다. 상시 서비스와 같은 태스크에 두면 응답 지연이 흔들린다 |

**`ai-batch` 는 `ai-service` 와 같은 이미지를 쓰고 진입점만 다르다.** 라벨 스키마와
어휘가 두 벌이 되면 배치가 만든 라벨을 서비스가 해석하지 못한다.

### 2.2 인증 경계

| 구간 | 자격증명 |
|---|---|
| 클라이언트 → ALB → `api-server` | 사용자 JWT (Spring Security) |
| `api-server` → `ai-service` | **없음.** 보안그룹으로 통제 (`03` §2.1) |
| `ai-service` → RDS / S3 | Task IAM Role + DB 역할 |

**사용자 JWT를 `ai-service` 로 넘기지 않는다.** 넘기는 순간 인가 로직이 두 런타임으로
쪼개지고, "누가 승인 권한을 판단하는가"에 답이 두 개가 된다.

`ai-service` 는 퍼블릭 ALB에 붙지 않는다. 인바운드는 `api-server` 태스크 보안그룹
하나뿐이다. **퍼블릭에 노출하기로 하면 그 전에 서비스 토큰을 먼저 넣는다.**

### 2.3 태스크 사양 (초기값)

| 항목 | `ai-service` | `ai-batch` |
|---|---|---|
| CPU / 메모리 | 1 vCPU / 2 GB | 2 vCPU / 4 GB |
| 태스크 수 | 2 (AZ 분산) | 0 (이벤트 기동) |
| 헬스체크 | `GET /healthz` 10s | — |
| 준비성 | `GET /readyz` — 모델·기준표·벡터 연결 확인 | — |
| 오토스케일 | ALB 요청수 + CPU 70% | — |
| 종료 유예 | 60s (진행 중 run 완료 대기) | 900s |

**`/readyz` 는 `/healthz` 와 다르다.** 프로세스가 살아 있어도 기준표나 벡터 인덱스를
못 읽으면 요청을 받으면 안 된다. 그 상태로 받으면 빈 결과가 나가고, 그것이 "AI가 답을
못 한다"로 기록된다.

## 3. 런타임 구성

### 3.1 LangGraph 노드 = 계약의 `steps[].name`

| 노드 | 하는 일 | 실패 시 |
|---|---|---|
| `assess` | 측정값 → 요인 점수·백분위 판정 (결정적) | 입력 수준 강등, 계속 |
| `retrieve` | 처방 어휘·라벨로 영상 검색 (결정적) | `video: null` 로 계속 |
| `compose` | 세션 편성 + 문장 생성 (**LLM 1회**) | 규칙 편성으로 강등 |
| `verify` | 인용·금지어휘·연령 일치 검사 | **거부.** 여기서만 전체 실패 |

**노드 이름을 바꾸면 계약이 바뀐다** — `03` §5.4의 `steps[].name` 이 이 이름이다.

**그래프에 체크포인터를 붙이지 않는다.** LangGraph 상태는 요청 수명 동안만 살고,
영속 상태의 정본은 `coach_runs` 테이블이다. 두 곳에 두면 승인 게이트가 어느 상태를
보는지 모호해진다.

**LLM 호출은 `compose` 한 곳뿐이다.** 비용·지연·실패가 한 곳에 모여야 관측과 강등이
쉽다.

### 3.2 환경변수 — 값은 이미지에도 코드에도 없다

| 이름 | 출처 | 용도 |
|---|---|---|
| `DATABASE_URL` | Secrets Manager | RDS 접속 |
| `ANTHROPIC_API_KEY` | Secrets Manager | `compose` · 라벨링 |
| `YOUTUBE_API_KEY` | Secrets Manager | 배치 메타 수집 |
| `KSPO_SERVICE_KEY` · `KSPO_ENDPOINT` | Secrets Manager | 공단 API |
| `MLFLOW_TRACKING_URI` | SSM Parameter | 모델 로드 |
| `VECTOR_BACKEND` | SSM Parameter | `pgvector` \| `faiss` |
| `SIM_THRESHOLD` | SSM Parameter | 유사도 임계값 — **아직 미측정** (`04` §6 ②) |

`KSPO_` 접두사는 공단 API 자격증명에만 쓴다 — 데이터 출처를 가리키는 이름이다.
앱 설정에는 접두사를 붙이지 않는다.

`.env` 는 커밋하지 않는다. 키가 늘면 `.env.example` 에 **이름만** 추가한다.

### 3.3 모델 버전

| 모델 | 라이브러리 | 버전 표기 |
|---|---|---|
| 분위수·밴드 | scikit-learn | `trajectory:YYYY-MM-DD.N` |
| 등급 보조 판정 | LightGBM | `grade:YYYY-MM-DD.N` |
| 영상 라벨러 | 외부 LLM | `labeler:<model>/<prompt-v>` |
| 임베딩 | 외부 API | `embed:<model>/<dim>` |

MLflow 레지스트리에서 **`Production` 별칭이 붙은 버전만** 서비스가 로드한다. 실험
결과가 곧바로 서비스로 가면 어느 모델이 어떤 답을 냈는지 사후에 맞출 수 없다.

## 4. 데이터 계층

### 4.1 `vector_store`

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE vector_store (
    chunk_id        text PRIMARY KEY,   -- "{source}:{natural_key}" 결정적
    source          text NOT NULL,      -- prescription|video|facility|criteria|safety
    text            text NOT NULL,
    citation_label  text NOT NULL,
    citation_url    text,
    metadata        jsonb NOT NULL DEFAULT '{}'::jsonb,
    embedding       vector(1024) NOT NULL,
    corpus_version  text NOT NULL,
    updated_at      timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX ON vector_store USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ON vector_store USING gin (metadata jsonb_path_ops);
CREATE INDEX ON vector_store (source, corpus_version);
```

**`vector(1024)` 의 차원은 확정이 아니다** — 임베딩 모델이 정해지지 않았다 (§7 ②).

`chunk_id` 는 결정적이다. 같은 원문을 다시 색인하면 같은 id가 나와야 인용이 이어진다.
청크 생성과 인용 표기 규칙은 `04-RAG-코퍼스-규약.md`.

**연령 필터는 애플리케이션이 아니라 `WHERE` 절에 있다.** 아이 질의에 성인 자료가
섞이는 것은 정확성이 아니라 안전 문제라, 걸러지지 않은 경로가 없어야 한다.

### 4.2 쓰기 경계

| | `ai-service` (온라인) | `ai-batch` | `api-server` |
|---|---|---|---|
| 읽기 | `vector_store` | `vector_store`·`exercise_videos` | 전부 |
| 쓰기 | **없음** | `vector_store`·`exercise_videos` 의 `ai_*` 컬럼 | 서비스 테이블 전부 |

**온라인 요청 처리 중 AI가 DB에 쓰는 경로는 존재하지 않는다.** 이것이 승인 게이트의
근거다 (`03` §8).

### 4.3 S3 레이아웃

| 접두사 | 내용 | 수명주기 |
|---|---|---|
| `raw/measurements/` | 공단 CSV | 영구 (저장소에 커밋하지 않는다) |
| `raw/frames/` | 라벨링용 프레임 | **30일 후 삭제** |
| `interim/` | 파이프라인 단계별 CSV | 90일 |
| `models/` | MLflow 산출물 | 버전별 보관 |
| `exports/` | 공개 라벨 데이터셋 | 영구 (메타데이터만) |

**`raw/frames/` 의 30일 만료가 재배포 금지 원칙을 운영으로 옮긴 것이다.** 프레임을
무기한 두면 "내부 분석 전용"이라는 전제가 시간이 지나며 흐려진다.

## 5. 관측

한 요청이 한 줄의 구조화 로그가 된다. **측정값 원본과 질문 원문은 로그에 넣지
않는다** — `profile_ref` 는 불투명 참조라 로그만으로 사람을 특정할 수 없다.

| 지표 | 목표 |
|---|---|
| 인용률 (비거부 응답 중 인용 ≥ 1) | **100%** — 임계가 아니라 절대값 |
| 연령 오적용 (아이 질의에 성인 자료) | **0건** — 임계가 아니라 절대값 |
| `p95` 지연 `/coach/messages` | < 5s |
| 거부율 (사유별) | 추세 관찰 |
| 규칙 편성 강등 비율 | < 5% (LLM 장애 신호) |

앞의 둘은 대시보드에서 다른 그래프와 같은 크기로 그리지 않는다.

## 6. 저장소

패키지는 **`family_fitness_ai`** 다. 코드 구역을 문서와 1:1로 맞춘다 — 어떤 코드의
규약이 어디 있는지 찾을 필요가 없게 한다.

```
docs/                       설계 · 인터페이스 계약
src/family_fitness_ai/
  api/        FastAPI 라우터              ← 03 §3~7
  graph/      LangGraph 노드 4개           ← §3.1
  rag/        청크 · 색인 · 검색 · 거부     ← 04
  stats/      분위수 · 요인 점수 정규화     ← 02 §5
  ingest/     공공데이터 수집              ← 02 §1
  labeling/   운동영상 라벨링              ← 02 §2.3
  common/     설정 · 공통 타입             ← §3.2
tests/
data/
  manifest.csv   원자료 목록 (커밋한다)          ← 02 §3.1
  release/       공개 산출물 (커밋한다) — 등급 문턱, 점수 분포, 원값 분위수
  raw/ interim/  커밋하지 않는다
```

**최상단은 이 넷뿐이다.** 산출 리포트를 위한 디렉터리를 따로 두지 않는다 — 재생성
가능한 것은 `data/` 아래에 두고 커밋하지 않는다.

품질 도구는 `ruff`(lint·format)·`mypy`·`pytest` 셋이다. CI는 이 셋만 돌린다.
