# AI-11 · 미션 편성 · `/v1/coach/runs`

계약은 `../03` §5. 응답 모양은 백엔드의 `StubAiGateway` · `LabelBasedProposalPlanner` ·
`ProposalConverter` 를 따른다.

---

## 1. 하는 일 — 비슷한 측정 기록의 처방을 가져온다

**흔한 추천 방식(가장 가까운 이웃)이다.** 사용자와 측정치가 가장 비슷한 공단 기록을
찾아, 그 사람들이 처방받은 운동 이름을 많은 순으로 쓴다.

**등급도, 모자란 요인도 판정하지 않는다.** 상위 등급은 항목마다 올려야 얻는 것이라
최종 등급의 원인을 따질 필요가 없다. LLM 은 무엇을 추천할지 정하지 않고 문구만 쓴다.

| 단계 (`steps[].name`) | 하는 일 | 실패 시 |
|---|---|---|
| `assess` | 요청에 온 입력 열(나이·성별·키·몸무게·측정 항목)을 확인한다 | 입력 수준 강등, 계속 |
| `retrieve` | 비슷한 기록 k명의 본운동 이름을 센다 → 운동 이름으로 영상 표를 찾는다 | `video: null` 로 계속 |
| `compose` | 세션에 담고 문구를 쓴다 (**LLM 1회**) | 고정 문구로 계속 |
| `verify` | 인용 1개 이상 · 금지 어휘 없음 | **거부** |

## 2. 매칭 규칙

| | |
|---|---|
| 후보 | 같은 연령대·성별의 공단 측정 기록 (처방이 있는 행) |
| 비교 열 | **요청에 온 열만** — 나이, 키(`001`)·몸무게(`002`), `measurements` 의 항목 코드. 후보도 그 열이 모두 있는 행만 |
| 거리 | 후보 집단의 평균·표준편차로 표준화한 유클리드 거리 |
| k | 200 (§3) |
| 결과 | k명의 본운동 이름을 세어 많은 순 |

측정값이 없으면(`L0`) 나이만 비교한다 — 같은 나이 인기순과 같다.

**입력 표는 원자료에서 만들고 커밋하지 않는다** (`../02` §4). 운동 이름은
[AI-6](AI-6-prescription-corpus.md) 어휘의 대표 표기로 맞춘다.

## 3. 채점 — 떼어 둔 사람의 실제 처방을 맞히는가

연령대마다 600명을 떼어 두고 (같은 회원의 다른 측정은 후보에서 뺀다), 추천 7개가 그
사람이 실제 받은 본운동을 얼마나 맞히는지 쟀다.

| 연령대 | 같은 나이·성별 인기순 | 매칭 k=50 | 매칭 k=200 |
|---|---|---|---|
| 유아기 | 36.3% | 36.1% | 39.5% |
| 유소년 | 36.3% | 34.3% | 37.5% |
| 청소년 | 44.1% | 43.7% | 46.5% |
| 성인 | 31.3% | 30.4% | 32.4% |
| 어르신 | 32.8% | 31.0% | 31.9% |

**인기순과 비슷하다 (±3%p).** 공단 처방은 측정치보다 나이·성별에 크게 좌우된다.
k=200 은 인기순보다 나빠지지 않고, 추천 7개 중 1~2개가 달라진다. k 가 작으면 흔들린다.

채점 스크립트는 매칭 모듈과 함께 검사로 넣는다.

## 4. 영상

**운동 이름 → 영상 표**를 [AI-7](AI-7-video-labeling.md) 이 만든다.

| 열 | |
|---|---|
| `exercise_name` | AI-6 어휘의 대표 표기 |
| `video_id` | YouTube 영상 ID. URL 은 백엔드가 만든다 |
| `start_sec` | 없으면 비운다 |

**표에 없으면 `video: null` 이다.** 계약상 결함이 아니다 (`../03` §5.7). 백엔드는
`video_id` 가 `exercise_videos` 에 있을 때만 붙인다 (`ProposalConverter`).

## 5. 응답 모양 — 백엔드와 같다

| | 규칙 | 백엔드 근거 |
|---|---|---|
| 미션 | 주행자마다 1개. 주행자가 없으면 동반자. `응원` 은 빠진다 | `StubAiGateway` |
| 참여자 | 대상 1명 + 동반자 | `StubAiGateway` |
| 세션 | `constraints.days_per_week` 개. `day_offset = i × 7 ÷ days_per_week` | `LabelBasedProposalPlanner` |
| 운동 | 세션마다 추천 순위대로 하나 | — |
| 분 | `constraints.minutes_per_session` | 둘 다 |
| 인용 | 처방 청크 `prescription:{연령구간}-{나이}-{성별}-본운동` + 영상이 있으면 `video:{video_id}`. 그 칸 청크가 없으면 같은 연령대·성별에서 나이가 가장 가까운 칸 | `StubAiGateway` |
| 문구 | `copy.child` · `copy.parent`. 금지 어휘는 `common/copy.py` | `LabelBasedProposalPlanner` |

**호출 방식은 백엔드가 부르는 대로 맞춘다** (`CoachRunExecutor` · `HttpAiGateway`).

| | 백엔드 동작 | AI 가 지킬 것 |
|---|---|---|
| `POST` | 2초 · 재시도 없음. 응답에서 `run_id` 만 쓴다 | run 을 등록하고 바로 `202`. `run_id` 는 40자 이하. 계산은 뒤에서 돌린다 |
| `GET` | 기다리지 않고 첫 호출, 1.5초 간격 최대 40회 · 호출마다 3초 | 바로 응답한다. 약 1분 안에 끝낸다 |
| 중복 | 가족·주 단위로 백엔드가 막는다 | AI 는 `409` 를 내지 않는다 |
| 오류 | `400`·`404`·`409` 는 실패 처리, 그 밖의 오류·시간 초과는 백엔드 대체 편성 | run 상태는 태스크 2개가 같이 보는 곳에 둔다 (§7 ④). 다른 태스크가 `404` 를 내면 실패다 |
| 입력 | 가족 전원을 보낸다 (`응원`·만 4세 미만 포함). 측정값이 없으면 `measurements: null` | `null` 을 받는다. `응원` 은 편성에서 뺀다 |

## 6. 검사

| 무엇 |
|---|
| 같은 요청이면 같은 추천이 나온다 |
| 요청에 없는 열로 비교하지 않는다 |
| 측정값이 없으면 같은 나이 인기순과 같다 |
| 표에 없는 운동은 `video: null` 이다 |
| LLM 을 실패시켜도 `succeeded` 가 나온다 |
| 인용 0 이면 `refused` 이고 `proposal` 이 `null` |
| `steps[].name` 이 `assess`·`retrieve`·`compose`·`verify` 다 |
| `응원` 역할이 편성 대상에서 빠진다 |
