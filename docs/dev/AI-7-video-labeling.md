# AI-7 · 운동영상 수집과 라벨링

공단 운동영상에 **연령대·체력요인·운동명**을 붙인다. 데이터 제약은 `../02` §2.3·§3.2,
청크 규약은 `../04` §1.

**이 이슈는 라벨이 얼마나 붙는지를 먼저 재는 일이다.** 붙지 않는 것이 정상 결과일 수
있고, 그때 `video: null` 이 결함이 아니라는 계약(`../03` §5.7)이 그 사실 위에 서 있다.

## 1. 알고 시작하는 것

공단 채널 전수 362편 / 재생목록 15종을 이미 수집해 본 결과다 (`../02` §2.3).

| | 편수 |
|---|---|
| 유아기 | 31 |
| 청소년 | 12 |
| 성인 | 5 |
| **연령 추정 불가** | **314 (87%)** |

- **유소년 전용 영상은 0편이다.** 「연령별 맞춤 운동」이 영유아·청소년·청년·중장년으로
  나뉘고 유소년 구간이 없다
- 설명문 228편(63%)이 체력요인을 언급하지 않는다. 25편은 요인 6~7개를 나열한 상용구다
- **설명문만으로 요인을 정할 수 있는 영상은 30% 수준이다**

> 2026-09-14 `channels.list` 로는 471편이다. 채널 전체를 다시 수집하면 위 수치를 고친다.

그래서 이 이슈의 성공 기준은 "전부 라벨링한다"가 아니다. **얼마나 붙었고 어디가
비는지를 수치로 남기는 것**이다.

## 2. 수집

```bash
python -m family_fitness_ai.labeling.collect --playlist PLBdpvOnWjVZmeshOCp06HAov4ieoNHoen  # 시험 묶음 · 영유아
python -m family_fitness_ai.labeling.collect                                                # 채널 전체
python -m family_fitness_ai.labeling.frames                                                 # 화면 이름표 · 맥에서만 (§2.1)
python -m family_fitness_ai.labeling.label                                                  # 규칙 라벨 · 리포트
```

| 규칙 | 왜 |
|---|---|
| `channels.list` → `playlists.list` → `playlistItems.list` → `videos.list` | **`search.list` 는 일일 100회 제한**이다 (`../02` §3.2) |
| 자막은 `youtube-transcript-api` 로 받고 한 편마다 1초 쉰다 | 공식 API(`captions.download`)는 영상 주인 권한이 필요하다. 몰아서 부르면 막힌다 |
| API 응답과 자막을 `data/raw/youtube/*.jsonl` 에 캐시한다 | 재실행이 다시 부르지 않는다 (`../02` §4). 새로 받으려면 파일을 지운다 |
| 자막이 없다는 결과는 캐시한다. **막히면 자막 받기만 멈추고** 나머지를 낸다 | 막힌 영상은 캐시하지 않아 다시 돌리면 끊긴 곳부터 받는다. 받지 못한 편수는 `caption` 빈칸으로 드러난다 |
| 영상·프레임·썸네일을 재배포하지 않는다 | `../02` §3.2 |

**D3(국민체력100 동영상 정보 API)는 이 이슈의 대상이 아니다.** 유튜브가 아니라 공단
운동영상 URL 을 주고, `성인` 영상뿐이다 (`../02` §1). 성인 영상 소스로 이후 적용한다.

### 2.1 화면 이름표 — `frames`

공단 영상은 구간마다 **왼쪽 위에 이름표**를 띄운다. 윗줄이 체력요인, 아랫줄이 운동 이름이다.

```
(응용편) 민첩성·순발력·협응성
빠르게 맞춰요
```

| 규칙 | 왜 |
|---|---|
| **영상 파일을 저장하지 않는다.** yt-dlp 가 받는 720p 이하 영상 바이트를 파이프로 ffmpeg 에 흘려 2초마다 프레임만 뽑는다 | `../02` §3.2 — 프레임 추출은 이 모듈에서만 한다. 영유아 31편은 이 규칙 전에 영상을 받아 뽑고 곧바로 지웠다 |
| 프레임은 `data/raw/frames/` 에 두고 **30일이 지나면 지운다** | `../01` §4.3. 실행할 때마다 지난 것을 지운다 |
| 두 자리만 읽는다 — 왼쪽 위(너비 45% · 높이 25%)와 아래 가운데 이름 막대(너비 28~80% · 높이 78~97%) | 운동 이름이 거기 뜬다 (§3.7 · §3.9). 나머지 글자는 로고·노래 가사·심박 표다 |
| 글자 인식은 macOS Vision (`ocrmac`) | 한국어를 읽고 설치가 가볍다. **맥에서만 돈다** |
| 읽은 글자를 `data/raw/youtube/screen.jsonl` 에 캐시한다 | 재실행이 영상을 다시 받지 않는다 |
| **영상이 없다(비공개·삭제)고 적힌 실패만** 사유를 캐시한다. 막힘·네트워크 끊김·알 수 없는 실패는 캐시하지 않고 멈춘다 | 다시 돌리면 끊긴 곳부터 받는다. 네트워크가 잠깐 끊겼을 때 20편이 "받을 수 없음"으로 캐시돼 건너뛰어진 적이 있다 |
| yt-dlp · ffmpeg · deno 가 필요하다 | yt-dlp 가 YouTube 의 스크립트 검사를 deno 로 푼다 |

**2026-09-14 화면을 읽기로 했다** (§6 ②를 닫았다). 한 편마다 5초 쉰다. **영상 파일은 받지
않는다** — 받지 않고 화면을 얻는 두 방법을 쟀다 (`IdpXx2gm90o` · 12분 18초).

| 방법 | 결과 |
|---|---|
| 스토리보드 (YouTube 미리보기 이미지) | **안 된다.** 가장 큰 것이 320×180 이라 이름표 글자가 뭉개진다 (`팔 벌려 뛰기` → `부팔 벌레비게`) |
| ffmpeg 가 스트림 주소를 직접 읽기 | 되지만 느리다. 전체를 훑는 데 370초 (2초마다 369장). 한 장만 뽑으면 1~2초 |
| **yt-dlp 가 받는 바이트를 파이프로 ffmpeg 에** | **된다 · 13초.** 영상은 파이프로만 흐르고 디스크에 닿지 않는다 — 이 방법을 쓴다 |

어느 방법이든 데이터는 네트워크로 받는다 — 디스크에 저장하지 않을 뿐이다.

## 3. 라벨링 — 규칙이 먼저다

**적혀 있는 것만 옮긴다.** LLM 보다 규칙을 먼저 쓴다 (`AGENTS.md` §7). LLM 은 규칙이
남긴 칸에만 쓴다 — 이후 적용 (§6 ①).

| 라벨 | 어디서 | 규칙 | 없으면 |
|---|---|---|---|
| `age_group` | 제목 > 재생목록 이름 | 연령대 이름과 `영유아`→`유아기` · `청년`→`성인`. **제목에 적힌 것이 앞선다** — 「청소년」 재생목록에 `[유소년]` 영상이 섞여 있다. 한 곳에 서로 다른 연령이 적히면 비운다 | **`null`. 추정하지 않는다** |
| `fitness_factors` | 제목 · 화면 이름표 윗줄 | 요인 이름. 표기 차이 `심폐체력`·`협응성` 만 합친다. 둘에서 나온 것을 합친다 | 빈 값 |
| `exercise_names` | 제목 > 화면 이름표 > 아래 이름 막대 > 설명문 > 자막 | [AI-6](AI-6-prescription-corpus.md) 어휘와 표기 차이까지 같을 때 (`identity`). 이름 막대는 통째로 같을 때만 (§3.9) | 빈 값 |
| `start_sec` | 화면 이름표 | 그 이름표가 처음 읽힌 시각. 운동 이름 → 영상 표에 싣는다 | `null` |
| `space`·`noise`·`equipment`·`intensity` | — | 규칙이 없다 | `null` |

### 3.1 추정하지 않는 것이 규칙이다

**연령 미상 영상은 아이 프로필에 내보내지 않는다** (`../02` §2.3). 그러므로 라벨러가
"아마 아이용일 것"으로 채우면 그 안전장치가 무력해진다.

| 판단 | 처리 |
|---|---|
| 제목·재생목록에 연령이 명시됨 | 그 값. **둘이 다르면 제목** — 「청소년」 재생목록의 `[유소년]` 영상 |
| 태그·설명문·자막에만 있음 | **`null`** |
| `유아` · `유치원생` · `초등학생` | 옮기지 않는다 — 연령대 이름이 아니다. 제목에 이것뿐이면 재생목록을 본다 |
| 한 곳에 서로 다른 연령 | `null` |
| 판단 불가 | `null` |

**태그를 보지 않는다.** `QU-eRtSLsm0` 은 제목이 「유치원생」, 재생목록이 「영유아」인데
태그가 `초등학생운동` 이다. 태그는 검색 노출용이다.

**근거 원문을 같은 행에 남긴다** (`../02` §4). 비운 라벨도 근거를 남긴다 — 한 곳에 서로
다른 연령이 적혀 비웠다면 그 줄을 적는다.

### 3.2 보지 않는 곳

| 무엇 | 왜 |
|---|---|
| 설명문의 해시태그 | 공단 상용구다. `#흔들어체조` 가 영유아 31편 중 28편 설명문에 있다 — 읽으면 28편이 `흔들어 체조` 영상이 된다 |
| 설명문의 요인 | 해시태그를 빼면 영유아 31편에서 제목에 없는 요인이 하나도 나오지 않는다 |
| 제목의 `균형` | 「균형있는 근육 발달」처럼 요인이 아닌 뜻으로 쓰인다 |
| 화면의 이름표 밖 글자 | 로고·노래 가사·말 자막이다. 이번에는 읽지 않는다 |

### 3.3 어휘 밖 운동명을 만들지 않는다

`exercise_names` 는 [AI-6](AI-6-prescription-corpus.md) 의 641개 안에서만 고른다.
계약(`../03` §5.7)이 `sessions[].exercise_name` 을 그 어휘로 제한하므로, 영상 라벨이
어휘 밖 값을 가지면 미션 편성에서 쓸 수 없는 라벨이 된다.

**공단 처방 어휘에 공단 영상의 이름표가 그대로 들어 있다** — `거북이 스트레칭`·`흔들어
체조`·`지그재그 달려요`·`밸런스 볼에 서요`. 그래서 문자열 일치가 먼저 통한다.

**부분 일치도 잡힌다.** `투명 줄넘기를 해요` 에서 `줄넘기` 가 잡힌다. 그래서 어디서
잡혔는지(`source`)와 그 줄(`evidence_text`)을 남긴다.

**비슷하기만 한 이름은 붙이지 않는다.** `QU-eRtSLsm0` 의 이름표 `#한발 서서 버티기` 는
어휘의 `한발 서서 균형잡기` 와 다른 표기다. 비슷한 이름은 대부분 다른 운동이다
([AI-6](AI-6-prescription-corpus.md) §4 ②) — §6 ⑦.

### 3.4 자막은 가장 덜 믿는다

긴 에피소드는 같은 여는 노래(`우리 모두 다같이`)로 시작해 `거북이 스트레칭` 으로
끝난다. 자막에서는 이 둘이 에피소드마다 잡힌다 — 틀린 것은 아니지만 그 운동의 영상으로
고를 것은 아니다. **같은 이름은 제목 > 화면 > 설명문 > 자막 순으로 하나만 남긴다.**
제목에서 잡힌 이름도 시각과 요인은 화면 이름표에서 가져온다.

자동 자막은 받아쓰기 오류가 있다 (`영유아기` → `역류하기`). 오류난 이름은 잡히지 않을
뿐 틀린 이름으로 잡히지는 않는다 — 어휘 밖이기 때문이다.

### 3.5 중장년은 쓰지 않는다

「🎯 연령별 맞춤 운동 : 중장년」 재생목록의 영상은 라벨하지 않고 화면도 읽지 않는다.
**서비스 대상이 아니다.** 리포트에 뺀 편수를 적는다.

### 3.6 백엔드 스키마

`exercise_videos` 의 연령·강도·공간·소음·기구가 nullable 이 됐다
([AI-13](AI-13-backend-contract-reconciliation.md) §3.6). `null` 은 "라벨 없음"이고,
라벨 없는 영상은 아이 프로필에 나가지 않는다 (`../02` §2.3).

**우리는 `exercise_videos` 에 직접 쓰지 않는다.** 그 테이블은 Spring Boot 소유이고
우리 DB 역할은 `ai_documents` 하나로 제한된다 (ADR-001). 라벨은 CSV로 내고 백엔드가
적재한다 ([AI-13](AI-13-backend-contract-reconciliation.md) §2.2).

### 3.7 화면 이름표 — 시험 3편

프레임을 2초마다 뽑아 전체 화면을 읽었다. `oCAjIRASiVI` 는 설명문에 구간 목록
(`00:16 빠르게 맞춰요` …)이 있어 정답과 맞춰 볼 수 있다.

| 영상 | 결과 |
|---|---|
| `oCAjIRASiVI` | 설명문 15구간이 **15개 모두** 화면에서 읽혔다. 시작 시각 차이 10초 안. 어휘에 있는 이름 13 |
| `qk0hXbltmIQ` | 제목·설명문에서 0개였던 이름이 4개 — `인사 체조`·`흔들어 체조`·`거북이 스트레칭`·`우리 모두 다같이` |
| `QU-eRtSLsm0` | 이름표는 읽힌다 (`#브릿지 자세`·`#사이드 점프`). **어휘와 표기가 달라 0개** (§3.3) |

- **아랫줄 이름은 깨끗하게 읽힌다.** 윗줄 요인은 가끔 틀린다 — `협응성` 을 `협성`·`형성`
  으로 읽는다. 그래서 **구간 윗줄의 30% 이상에서 읽힌 요인만 붙인다**
- **한 프레임에만 읽힌 이름은 잡음으로 버린다.** 이름표가 잠깐 사라졌다 다시 떠도 사이에
  다른 이름이 없으면 한 구간으로 잇는다
- 윗줄이 `안정성·이동성·조작성` 인 이름표가 있다. 체력요인이 아니라 기본운동기술이라 옮기지 않는다
- **제목과 윗줄의 요인이 다를 수 있다.** `OpnELu5j4nk` 는 제목이 `유연성` 인데 스트레칭 구간
  윗줄은 `심폐지구력·협응성` 이다 (프레임으로 확인). 공단이 적은 그대로 둘 다 옮긴다 — 어느
  쪽이 맞는지 고르지 않는다
- 전체 화면 1,200장을 읽는 데 약 4분 걸렸다. 모듈은 왼쪽 위만 읽는다

### 3.8 LLM 층 — 로컬과 Claude 를 바꿔 끼운다

규칙이 남긴 칸(`space`·`noise`·`equipment`·`intensity`)에만 쓴다. **LLM 은 판단하지
않는다** (`AGENTS.md` §7) — 화면에 **보이는 것**(쓰는 기구, 뛰는 동작, 자세)을 고정
목록에서 고르게 하고, 라벨로 바꾸는 것은 코드다.

| | `LABELER_BACKEND=llama` (기본) | `LABELER_BACKEND=claude` |
|---|---|---|
| 어디서 | 로컬 `llama serve` (OpenAI 호환 API) | Anthropic API |
| 외부 호출 | 없다 | **있다 — 비용이 든다** (`AGENTS.md` §3) |
| 모델 | 서버가 띄운 것. 시험은 `Qwen3-VL-8B-Instruct` Q4_K_M | `LABELER_MODEL`. 비우면 `claude-opus-5` |
| 출력 | JSON 스키마로 묶는다 | 같다 (`output_config.format`) |
| 거절 | — | 서버가 다른 모델로 다시 돌린다 (`fallbacks: "default"`). 그래도 거절이면 칸을 비운다 |

호출부는 `observe(이미지, 지시, 스키마) → JSON` 하나만 안다. 잘린 답과 거절은 예외로
올리고 그 칸을 비운다 — 지어내지 않는다.

**시험 — 로컬 `Qwen3-VL-8B-Instruct` Q4_K_M · 구간 5개 · 구간마다 프레임 4장** (2026-09-14).
정답은 프레임을 눈으로 보고 정했다. 시간은 화면 읽기가 함께 돌던 중에 잰 것이다.

| 해상도 | 한 구간 | 동작 (점프 · 이동) · 자세 | 기구 |
|---|---|---|---|
| 640×360 | 약 10초 | 5구간 모두 눈으로 본 것과 맞다. 자세 1곳이 틀렸다 (쪼그려 앉음 → `서서`) | **5구간 중 2구간만 맞다.** 미트를 `블록` 으로 읽고 매트를 놓쳤다 |
| 1280×720 | 약 30초 | 같다 | 나아지지 않았다. 없는 `줄넘기` 를 붙였다 |

**기구는 이 모델로 붙이지 않는다** — 해상도를 올려도 틀린 답이 그대로다. 동작은 맞았지만
5구간이라 믿기 이르다. 이후 적용: 구간을 늘려 동작을 다시 재고, 그것을 `noise`·`space` 로
옮기는 규칙을 정한다. Claude 쪽은 자격증명이 없어 같은 시험을 돌리지 못했다.

### 3.9 아래 이름 막대 — 청소년·유소년 「비대면 표준 운동 프로그램」

이 묶음은 왼쪽 위에 **묶음 이름**(`연령별 유소년 교실근력운동`)만 띄우고, **운동 이름은 화면 아래
가운데 막대**에 띄운다 (`의자 잡고 팔굽혀 버티기`). 막대 바로 위에 설명 한 줄이 붙는다. 왼쪽
위만 읽었을 때 청소년 재생목록 12편에서 화면 이름이 7개밖에 나오지 않았다 (프레임으로 확인).

그래서 아래 가운데(너비 28~80% · 높이 78~97%)도 읽는다. 이미 읽은 영상은 디스크에 남은
프레임에서 이 자리만 읽는다 — YouTube 에 다시 가지 않는다.

**이름이 어휘와 통째로 같을 때만 붙인다.** 같은 자리에 설명·안전 문장도 뜬다 (`사이드 스텝으로
활동한다`) — 부분 일치를 허용하면 문장 속 낱말이 운동 이름이 된다.

| 막대 글자 | 붙는 이름 |
|---|---|
| `다리 뻗어 상체 숙이기` | `다리뻗어 상체 숙이기` — 표기 차이 |
| `넙다리 안쪽 늘리기 (나비자세)` | `나비자세` — 통째가 어휘에 없으면 괄호 속 이름도 본다 |
| `3. 힘차게 던져요!!` | `힘차게 던져요` — 번호·느낌표를 뗀다 |
| `책상에서 팔굽혀펴기` | **붙이지 않는다** — `팔굽혀펴기` 와 다른 동작일 수 있다 |

`Eg3GpTv7z8s` 한 편 시험: 944장 57초, 구간 53개(소개 문장 포함). 막대의 운동 이름은 대부분
어휘에 없다 (`의자 잡고 팔굽혀 버티기`·`서서 재기차기`) — 읽기가 아니라 어휘의 공백이다 (§6 ⑦).

**43편 결과** — 막대에서 37건 · 5편 · 어휘 9개가 붙었다. 전부 통째 일치다 (눈으로 확인).

- **다섯 편이 같은 준비·정리운동을 갖는다** — `나비자세`·`고양이 자세`·`아기자세`·`다리뻗어 상체
  숙이기`·`엎드려 상체 들어올리기`·`양팔 벌려 전신 비틀기`. 본운동 이름은 `왕복달리기`·`서서 다리
  모으고 벌리기` 둘만 어휘에 있다
- `척추 들어올리기 (고양이자세)` 는 두 이름이 같은 시각으로 붙는다 — 둘 다 어휘에 있다

### 3.10 공통 준비·마무리는 뒤로 미룬다

긴 에피소드들은 같은 여는 노래·마무리 체조를, 청소년 「비대면 표준 운동 프로그램」은 같은
준비·정리운동을 영상마다 넣는다. 틀린 이름은 아니지만 그 영상의 본운동이 아니다
(2026-09-14 결정 — 빼거나 순위를 낮춘다).

**같은 재생목록 3편 이상에 똑같이 나오는 이름을 공통으로 표시한다.** 제목에서 잡힌 이름은
표시하지 않는다 — `EP03.거북이 스트레칭` 에서는 그것이 본 내용이다.

| 43편 실측 | 나오는 편수 |
|---|---|
| 영유아 `인사 체조`·`흔들어 체조`·`거북이 스트레칭`·`우리 모두 다같이` | 11 |
| 청소년 `나비자세` | 6 |
| 청소년 `고양이 자세`·`척추 들어올리기`·`아기자세`·`다리뻗어 상체 숙이기`·`엎드려 상체 들어올리기`·`양팔 벌려 전신 비틀기` | 5 |
| 그다음 — 영유아 `엉금엉금 기어요` (본운동) | 2 |

5편과 2편 사이가 비어 있어 기준을 3~5 어디에 두어도 결과가 같다.

- `video_labels.csv` — `exercise_names` 는 본운동만 두고, 공통은 `common_exercise_names` 로 옮긴다
- `video_exercises.csv` — 행은 남기고 `common` 을 표시한다. 이름마다 본운동 행을 먼저 적는다

**43편 결과** — (운동, 영상) 142행 중 **76행이 공통**이다. 본운동이 하나라도 붙은 영상은
**24편** (공통까지 치면 32편), 본운동이 2개 이상인 영상은 14편이다.

확인용) `IpBlocked` 가 났다. 자막 수치는 막힘이 풀린 뒤 다시 돌려 잰다.

## 5. 초등 페르소나가 두 번 빈다

`../02` §2.2 의 측정 공백(만 7~10세 0건)과 §2.3 의 영상 공백(유소년 0편)이 겹친다.
**초등 페르소나는 측정도 영상도 비는 구간이다.**

이 사실을 이 이슈에서 감추지 않는다. 계약은 두 공백을 모두 정상 응답으로 정의해
두었다 — `factors: []` (`../03` §2.4) 와 `video: null` (`../03` §5.7). 서비스가
그 구간에서 무엇을 보여줄지는 화면의 결정이고, 그 판단의 재료가 §4 리포트다.
