## 1. 이미지 하나, 진입점 둘

**`ai-batch` 는 `ai-service` 와 같은 이미지를 쓰고 진입점만 다르다** (`../01` §2.1).
라벨 스키마와 어휘가 두 벌이 되면 배치가 만든 라벨을 서비스가 해석하지 못한다.

| 컨테이너 | 진입점 | 태스크 |
|---|---|---|
| `ai-service` | `uvicorn ... api.app:app` | 상시 2개 (AZ 분산) |
| `ai-batch` | `python -m family_fitness_ai.<batch>` | 0개 · 이벤트 기동 |

`data/release/` 산출물을 이미지에 넣는다. 628KB이고, 넣으면 `/readyz` 의 산출물
확인이 배포 시점에 끝난다.

## 2. 배포 형상

`../01` §2.3 의 초기값을 그대로 쓴다.

| | `ai-service` | `ai-batch` |
|---|---|---|
| CPU / 메모리 | 1 vCPU / 2 GB | 2 vCPU / 4 GB |
| 태스크 | 2 | 0 |
| 헬스체크 | `GET /healthz` 10s | — |
| 종료 유예 | 60s | 900s |

**`ai-service` 는 퍼블릭 ALB에 붙지 않는다** (`../01` §2.2). 인바운드는 `api-server`
태스크 보안그룹 하나뿐이다.

> ⚠ **퍼블릭에 노출하기로 하면 그 전에 서비스 토큰을 먼저 넣는다** (`../03` §2.1).
> 순서를 바꾸지 않는다.

**사용자 JWT를 `ai-service` 로 넘기지 않는다** (`../01` §2.2). 넘기는 순간 인가 로직이
두 런타임으로 쪼개진다.

## 3. 비밀값

`../01` §3.2 의 표를 그대로 옮긴다. **값은 이미지에도 코드에도 없다** — Secrets
Manager와 SSM Parameter Store에서 태스크 정의가 주입한다.

`.env` 는 커밋하지 않는다. 키가 늘면 `.env.example` 에 **이름만** 더한다.

## 4. 관측 — 두 지표는 임계가 아니다

| 지표 | 목표 |
|---|---|
| **인용률** (비거부 응답 중 인용 ≥ 1) | **100%** — 절대값 |
| **연령 오적용** (아이 질의에 성인 자료) | **0건** — 절대값 |
| `p95` 지연 `/coach/messages` | < 5s |
| 거부율 (사유별) | 추세 관찰 |
| 규칙 편성 강등 비율 | < 5% |

**앞의 둘은 대시보드에서 다른 그래프와 같은 크기로 그리지 않는다** (`../01` §5).

한 요청이 한 줄의 구조화 로그가 된다. **측정값 원본과 질문 원문은 로그에 넣지
않는다** ([AI-3](AI-3-service-skeleton.md) §2.5).

## 5. 모델 버전

**MLflow 레지스트리에서 `Production` 별칭이 붙은 버전만 서비스가 로드한다**
(`../01` §3.3). 실험 결과가 곧바로 서비스로 가면 어느 모델이 어떤 답을 냈는지
사후에 맞출 수 없다.

## 6. CI를 넓힌다

지금 CI는 `ruff`·`mypy`·`pytest` 셋이다 (`../01` §6). 여기에 더한다.

| 더하는 것 | 왜 |
|---|---|
| 이미지 빌드 | 배포 직전에 처음 빌드하지 않는다 |
| `/healthz`·`/readyz` 스모크 | 기동 자체가 깨진 것을 배포 뒤에 알지 않는다 |

**품질 도구는 셋으로 유지한다** (`../01` §6). 검사 종류를 늘리지 않고 대상을 넓힌다.

### 6.1 백엔드는 컨테이너가 아니라 모놀리스다

`../01` §2 는 `api-server`·`ai-service`·`ai-batch` 세 컨테이너를 그렸다.
**백엔드는 Spring Modulith 모듈러 모놀리스 하나다** (ADR-001 — "No microservices
separation"). 스택도 `Kotlin · Spring Boot 4.1.1 · Java 25 · Google OAuth` 라
`../01` §2 의 `Spring Boot 3 · Java 17 · JWT` 와 다르다
([AI-13](AI-13-backend-contract-reconciliation.md) §2.3).

**우리 쪽 컨테이너 둘은 그대로 유효하다.** 나눈 이유(`../01` §2.1 — LLM 실패를
API 스레드에 묶지 않는다, 배치가 응답 지연을 흔들지 않는다)가 백엔드 형상과 무관하다.

**DB는 하나를 공유한다.** 우리 역할은 `ai_documents` 로 제한되므로, 보안그룹뿐
아니라 **DB 역할 자체가 경계**다 — `../01` §4.2 가 코드 검토로 지키려던 것을
권한이 지킨다.

### 6.2 일요일 20시에 몰린다

주간 코치가 **일요일 20시 CRON**으로 돈다 (유저플로). 우리 `../03` §5 는 사용자가
버튼을 누르는 것만 상정했다.

한 run이 15~40초다. 가족 수만큼이 한 시각에 몰리면 `../01` §2.3 의 태스크 2개와
ALB 요청수 오토스케일로는 늦다 — **오토스케일은 부하가 온 뒤에 뜬다.**

| 필요한 것 | 왜 |
|---|---|
| 가족 수 추정 | 규모를 모르면 사양을 정할 수 없다 |
| 큐로 흘릴지 동시에 받을지 | 동시에 받으면 LLM 레이트 리밋에 먼저 걸린다 |
| CRON 시각 분산 | 20시 정각이 아니라 창으로 펴면 사양이 내려간다 |

**지금 정하지 않는다.** 가족 수가 나와야 하는 계산이고, 그 전에 정하면 근거 없는
사양이 된다.
