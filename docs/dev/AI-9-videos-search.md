# AI-9 · `POST /v1/videos/search`

계약은 `../03` §4. [AI-8](AI-8-vector-index.md) 의 검색을 계약 모양으로 내보낸다.
**새 계산이 거의 없는 얇은 층이다.**

---

## 1. 공간·소음·기구 필터는 받는다 — `../03` §4.1 이 낡았다

`../03` §4.1 은 이렇게 못박았다.

> **공간·소음·기구·길이 필터는 받지 않는다.** 라벨이 그 필드를 갖지 않아 거를
> 데이터가 없다. 요청에 넣으면 무시가 아니라 `400` 이다

**그 전제가 사실이 아니다.** 백엔드 `exercise_videos` 는 `space`·`noise`·
`intensity` 를 `not null` 로, `equipment` 를 nullable로 갖는다. 유저플로도 RAG 검색이
"age, noise level, space requirements"로 거른다고 적는다
([AI-13](AI-13-backend-contract-reconciliation.md) §2.1).

`../03` §12 는 이 필터의 조건을 "라벨 스키마가 그 필드를 라벨할 때"로 두었다.
**조건이 충족됐다.**

> **계약 필드가 바뀌는 변경이라 `AGENTS.md` §3 대로 합의가 먼저다**
> ([AI-13](AI-13-backend-contract-reconciliation.md) §8 ①). 합의 전에는 `../03`
> §4.1 대로 `400` 을 유지한다 — 문서와 코드가 갈라지는 것보다 낫다.

**다만 라벨이 실제로 붙는지는 별개다.** `not null` 이 값을 강요할 뿐 정확도를
보장하지 않는다 ([AI-7](AI-7-video-labeling.md) §4). 걸 수 있는 필터와 믿을 수 있는
필터는 다르다.

## 2. 나머지 규칙

| 규칙 | 근거 |
|---|---|
| `age_group` 은 **필수**다 | 정확성이 아니라 **안전** 때문이다 (`../03` §4.1) |
| `fitness_factors` 와 `exercise_names` 중 최소 하나 | `../03` §4.1 |
| 어휘 밖 `exercise_names` 는 **무시**한다 | 400이 아니다. `../03` §4.1 |
| `video_id` 만 돌려준다 | 제목·URL·길이는 API 서버가 조인한다 (`../03` §1) |

**무시와 400이 갈리는 지점을 헷갈리지 않는다.** 어휘 밖 운동명은 사용자 입력이라
무시하고, 받지 않기로 한 것은 호출자 버그라 `400` 이다.

**조인 키를 정해야 한다.** 우리는 YouTube video id를 보내고(`../03` §4.2),
`exercise_videos` 는 `id uuid` 와 `youtube_id varchar(32)` 를 둘 다 갖는다. 어느
쪽으로 조인할지 합의가 필요하다 (§4 ①).

## 3. `filtered_out` 은 라벨 공백을 재는 값이다

```json
{"hits": [], "filtered_out": {"age_group": 3, "below_threshold": 5}}
```

**0건은 결함이 아니다** (`../03` §4.2). 전수 362편 중 314편이 연령 미상이라
아이 프로필 검색은 자주 빈다 (`../02` §2.3).

`filtered_out` 을 0으로 채우거나 생략하지 않는다. 이 값이 [AI-7](AI-7-video-labeling.md)
의 라벨 공백이 서비스에서 얼마나 드러나는지를 재는 유일한 계기다.

## 4. 검사

| 무엇 | 왜 |
|---|---|
| 아이 연령대 결과에 연령 미상 영상이 0건 | `../02` §2.3. 성인·어르신에는 내보낸다 |
| `hits: []` 에도 `filtered_out` 이 채워진다 | §3 |
| 어휘 밖 운동명이 `400` 이 아니다 | `../03` §4.1 |
| 응답에 제목·URL이 없다 | `../03` §1 |
| `hits[].score` 가 0.0~1.0 | 요인 점수(0~100)와 다른 값이다 (`../03` §4.2) |
