# AI-4 · `POST /v1/fitness/assessment`

계약은 `../03` §3. 이미 있는 것을 계약 모양으로 내보내는 일이다 — 새 계산은
`child_scope`/`parent_scope` 분리와 문구 생성뿐이다.

| 필요한 것 | 어디 있나 |
|---|---|
| 요인 점수 · 백분위 · 밴드 | `stats/assess.py` — **있다** |
| 등급 · 또래 등급 분포 | [AI-2](AI-2-grade-card.md) |
| 앱 골격 · 오류 · 설정 | [AI-3](AI-3-service-skeleton.md) |
| 문구 (`copy`) | 이 이슈 |

---

## 1. 산출물이 곧 런타임이다

`stats/assess.py` 의 `Reference` 는 이미 "기동 시 한 번 올려두고 요청마다 조회·
보간만" 하는 모양이다. **그것을 그대로 쓴다.** 요청마다 CSV를 읽지 않는다.

산출물 넷은 합쳐 617KB다 ([AI-1](AI-1-age-band-distribution.md) §3). 메모리에
올려 두는 데 문제가 없고, DB도 외부 호출도 필요 없다. **`assessment` 응답에는
LLM 호출이 없다** — `../01` §3.1 이 LLM 호출을 `compose` 한 곳으로 묶었다.

---

## 2. 입력 수준

`../03` §3 의 표를 그대로 따른다. **측정값은 선택 입력이고, 대부분은 `L1` 에
머문다.**

| `input_level` | 판단 기준 |
|---|---|
| `L0` | 나이·성별만 |
| `L1` | 신장·체중이 있다 |
| `L2` | 점수가 난 항목이 하나 이상 있다 |

**`measurements` 가 왔다고 `L2` 가 아니다.** 그 연령 구간의 기준항목이 아니면 점수가
안 나온다 — `stats/assess.py` 가 이미 `not_scored` 로 갈라 두었다. 하나도 안 나오면
`L1` 이다.

**측정값이 없어도 `200` 이다.** `factors: []` 는 오류가 아니다 (`../03` §2.4).

---

## 3. 응답 조립

### 3.1 `child_scope`

`focus_one` **하나**뿐이다. 점수·백분위·체중이 페이로드에 들어가지 않는다 —
아이 화면이 실수로 노출할 값이 애초에 없게 한다 (`../03` §2.6).

- `L2` 면 점수가 가장 낮은 요인 하나. `stats/assess.py` 의 `focus_one` 이 이미 낸다
- `L0`·`L1` 이면 연령대 일반 제안. **점수가 없으므로 요인을 고르는 근거도 없다** —
  연령대별 고정 제안이고, 그 근거는 코퍼스가 서면 안전지침 청크가 된다 (`../04` §1)

### 3.2 `parent_scope`

| 필드 | 출처 |
|---|---|
| `grade` | [AI-2](AI-2-grade-card.md) §1. `L2` 가 아니면 `null` |
| `peer_distribution` | [AI-2](AI-2-grade-card.md) §4 의 CSV. **`L0` 에서도 낸다** |
| `factors` | `stats/assess.py`. `L2` 가 아니면 빈 배열 |
| `copy.strength` · `copy.focus` | §3.3 |

`peer_distribution` 이 `L0` 에서도 나가는 것은 `../03` §3 의 표가 그렇게 정하기
때문이다 — 측정값이 없어도 "우리 또래는 이렇다"는 보여줄 수 있다.

### 3.3 문구 — 템플릿이다. LLM이 아니다

`../01` §3.1 이 LLM 호출을 `compose` 한 곳으로 묶었다. `assessment` 는 그 그래프를
타지 않으므로 **문구는 규칙으로 만든다.**

| 자리 | 규칙 |
|---|---|
| `child_scope.focus_one.copy` | 요인별 고정 문구. 아이 화면 문구는 **고쳐 쓰지 않는다** (`../03` §3.3) |
| `parent_scope.copy.strength` | `band == strength` 인 요인 중 점수 최고 |
| `parent_scope.copy.focus` | 점수 최저 요인 |

**"부족"·"미달"·"하위"를 쓰지 않는다** (`../03` §2.6). 밴드 문구는 `../03` §3.5 의
표가 정본이다 — `strength` 는 "잘하고 있는 영역", `growth` 는 "지금 키우기 좋은
영역"이다.

문구 표를 코드에 흩지 않고 한 모듈에 모은다. 금지 어휘 검사(`../03` §5.4 의 `verify`)가
나중에 같은 표를 봐야 한다.

### 3.4 `item_label` 은 `item_name` 과 다르다

같은 코드 `020` 이 유소년은 15m, 청소년·성인은 20m 왕복 오래달리기다 (`../03` §3.5).
`stats/items.py` 의 `ITEMS` 는 `item_name`(데이터 항목명)만 갖는다.

**`item_label` (연령대별 실제 시험명)은 `stats/items.py` 의 `CRITERIA_COLUMNS` 에
이미 있다** — 기준표 열 머리글이 `15m왕복오래달리기(회)` 다. 열 머리글에서 단위
괄호를 떼면 그 연령대의 시험명이 된다. 두 번째 표를 만들지 않는다.

---

### 3.5 백엔드가 항목을 이름으로 저장한다

`fitness_test_items.item varchar(30)` 이 `악력`·`유연성` 같은 **이름**이다
([AI-13](AI-13-backend-contract-reconciliation.md) §3.5).

`../03` §3.1 이 정확히 이 문제를 경고했다 — **"코드가 식별자이고 이름은 표기다."**
기준표는 `제자리멀리뛰기`, 컬럼정의서는 `제자리 멀리뛰기` 다. 백엔드 유저플로도
"Fitness item code mappings ... remain pending validation"으로 이것을 미결에 두고
있다.

**`../02` §5.1 의 기준항목 표와 `../03` §9 의 코드표가 그 답이다.** 우리는 계약대로
3자리 코드를 받고 낸다. 이름으로 조인하는 쪽이 어디서 깨지는지는 우리가 이미
문서화해 두었으므로, 그것을 넘긴다.

**그리고 `score` 컬럼이 없다.** `percentile`·`grade` 는 있다. `../02` §5 전체가
요인 점수 0~100을 만드는 규약이고 `../03` §3.5 의 `factors[].score` 가 그 값인데,
저장할 자리가 없으면 화면이 진입할 때마다 우리를 다시 부르거나 점수를 버려야 한다.
`../03` §3 은 **"프로필 생성이나 측정값 저장·수정 직후 1회"** 호출을 전제한다.

## 4. 저표본

`n < 30` 인 칸의 처리는 `../02` §6 ③ 이고, **확정 전 기본값은 `score`·`percentile`
을 `null` 로 내리는 것**이다 (`../03` §3.5).

현재 `stats/assess.py` 는 점수를 낸 뒤 `low_sample` 만 세운다 —
[AI-1](AI-1-age-band-distribution.md) 이 `linear` 폴백으로 값을 만들어 두었기
때문이다. **계약의 기본값과 다르다.**

| 대상 | 지금 | 계약 기본값 |
|---|---|---|
| CLI (`stats.assess`) | 선형 폴백 점수를 낸다 | — (진단용이라 그대로 둔다) |
| API 응답 | — | `null` 로 내린다 |

**API 경계에서 내린다.** 산출물이나 `stats` 안에서 지우면 진단 CLI도 함께 눈이
멀고, 확정이 반대로 나면 되돌릴 값이 없다. 해당하는 칸은 4개다
([AI-1](AI-1-age-band-distribution.md) §4).

## 5. 검사

| 무엇 | 왜 |
|---|---|
| `child_scope` 에 `score`·`percentile`·`weight` 키가 없다 | 노출 사고를 스키마로 막는다 (`../03` §2.6) |
| `005`·`006` 이 오면 `400 ITEM_NOT_ALLOWED` | `../03` §9 |
| 측정값 없이 `200` · `factors: []` | 빈 배열은 오류가 아니다 |
| 만 7~10세에 `factors: []` · `grade: null` | 측정 0건 구간 (`../02` §2.2) |
| 문구에 금지 어휘가 없다 | "부족"·"미달"·"하위" (`../03` §2.6) |
| 유아기 `age_unit: 개월` 이 그대로 조회된다 | 세로 환산은 **내림** (`../02` §2.4) |

**`../02` §5.6 의 실측 예시(유소년 여 11세)를 회귀 검사로 박아 둔다.** 근력 67.6 ·
유연성 45.3 · 심폐지구력 85.9 · 순발력 41.2. 산출물이 다시 만들어졌을 때 점수의 뜻이
바뀌었는지가 이 넷에서 드러난다.
