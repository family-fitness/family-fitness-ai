# AI-6 · 처방 어휘와 처방 청크

코퍼스의 주축을 만든다. 규약은 `../04` §1·§2.

**운동처방 텍스트는 별도 API가 아니라 측정 데이터의 처방 컬럼에 이미 들어 있다**
(`../04` §1). 새로 받을 원자료가 없다 — [AI-1](AI-1-age-band-distribution.md) 이 읽는
그 CSV에 있다.

---

## 1. 두 가지 산출물

같은 원문에서 성격이 다른 둘이 나온다. **나누는 이유는 쓰는 곳이 다르기 때문이다.**

| 산출물 | 무엇 | 쓰는 곳 |
|---|---|---|
| **처방 어휘** | 고유 운동명 638개의 목록 | `../03` §4.1 `exercise_names` 의 허용 집합, §5.7 `sessions[].exercise_name` |
| **처방 청크** | 처방 항목 1건 = 청크 1개 | 검색 대상 (`../04` §1) |

어휘는 **닫힌 집합**이다. `../03` §4.1 이 "어휘 밖 문자열은 무시된다"고 정했으므로
그 집합이 파일로 있어야 한다. 청크는 검색되는 문서다.

---

## 2. 실행

```bash
python -m family_fitness_ai.rag.prescription --data-dir ~/받은자료/kspo-measure
```

원자료를 읽는 두 번째 경로다. `ingest/measurements.py` 는 점수 대상 열만 남기므로
**처방 컬럼을 남기도록 열 목록을 넓힌다** — 파일을 두 번 읽지 않는다.

---

## 3. 산출물

### `data/release/exercise_vocabulary.csv` — 처방 어휘

`data/release/` 에 커밋한다. 계약이 참조하는 닫힌 집합이라, 코드와 함께 버전이
움직여야 한다.

| 열 | 내용 |
|---|---|
| `exercise_name` | 정규화된 운동명. **이것이 계약의 값이다** |
| `raw_forms` | 원자료에 나타난 표기 변형. 세미콜론 구분 (`../02` §4) |
| `count` | 전수에서의 출현 횟수 |
| `age_groups` | 이 운동이 나타난 연령대. 세미콜론 구분 |
| `fitness_factors` | 붙은 요인. 판정되지 않으면 빈칸 |

**표기 변형을 버리지 않는다** (`../02` §4). `제자리멀리뛰기` 와 `제자리 멀리뛰기` 는
같은 운동이고 자료마다 다르게 적혀 있다 (`../03` §3.1). 정규화 결과만 남기면 다음에
재수집했을 때 같은 정규화가 나오는지 확인할 방법이 없다.

**638은 표본 추정이 아니라 전수 값이다** (`../04` §1). 산출된 수가 638과 다르면
정규화 규칙이 달라진 것이므로, 그 차이를 리포트에 남긴다.

### `data/interim/prescription_chunks.csv` — 처방 청크

커밋하지 않는다 (`../02` §4). 색인의 입력이다.

| 열 | 내용 |
|---|---|
| `chunk_id` | `prescription:{연령구간}-{나이}-{성별}-{일련}` (`../04` §1) |
| `source` | 고정값 `prescription` |
| `text` | 임베딩 대상 원문. **요약하지 않는다** (`../04` §2.1) |
| `citation_label` | `국민체력100 운동처방 · {연령구간} {나이}세` |
| `citation_url` | 비어 있다 |
| `age_group` · `fitness_factor` · `grade` | `metadata` 로 들어갈 필터 값 (`../04` §2.2) |
| `exercise_names` | 이 처방문에 나온 어휘. 세미콜론 구분 |

**`age_group` 이 빈 청크는 만들지 않는다** (`../04` §2.2). 처방 청크는 `age_group` 이
반드시 채워져 있어야 하고, 비어 있으면 색인 단계가 아니라 **여기서** 걸러진다.
연령 무관으로 위장한 성인 처방이 아이에게 가는 경로를 만들지 않기 위해서다.

## 4. `일련` — 결정적이어야 한다

`../04` §6 ④ 가 미결이고 **확정 전 기본값은 처방 원문의 내용 해시**다.

`natural_key` 는 원자료의 내용에서만 만든다 (`../04` §1). 순번을 쓰면 재수집 때
파일 순서가 달라지는 것만으로 `chunk_id` 가 바뀌고, `missions.evidence` 에 저장된
인용이 끊긴다.

**백엔드가 같은 선택을 이미 했다.** `ai_documents.content_hash char(64)` 가
SHA-256이고 `(content_hash, embedding_version)` 이 유니크다
([AI-13](AI-13-backend-contract-reconciliation.md) §5). 우리 기본값과 맞으므로 이
미결은 사실상 답이 나온 쪽이다 — 다만 **"같은 해시면 같은 행을 upsert한다"는
규칙이 문서에 없다** ([AI-8](AI-8-vector-index.md) §2.2).

**해시의 입력을 문서에 적는다.** 무엇을 해싱했는지가 없으면 다음 사람이 같은 값을
재현하지 못한다. 원문 문자열 하나만 넣을지, 연령·성별까지 넣을지가 §6 ①이다.

## 5. 코퍼스가 작으면 검색이 근거를 더하지 않는다

`../04` §1 이 경고한 것이다. **소스별 청크 수를 세어 리포트에 남긴다.**

| 세어야 하는 것 | 왜 |
|---|---|
| 처방 청크 수 | 638 어휘가 몇 개의 청크에 흩어져 있는가 |
| 중복률 (같은 `text` 의 청크) | 처방문이 상용구면 검색이 변별하지 못한다 |
| 연령대별 청크 수 | 아이 프로필 검색이 비는지는 여기서 먼저 보인다 |
| 청크 길이 분포 | 400토큰 초과·50토큰 미만이 몇 개인가 (`../04` §2.1) |

표본 301행 중 261행(87%)에 처방문이 있었다 (`../04` §1). **전수에서도 87%인지는
재지 않았다** — 이 이슈가 처음 재는 값이다.

## 7. 범위 밖

- **등급 기준표 청크(`criteria`)** — `grade_thresholds.csv` 에서 만든다. 원자료가
  이미 있어 [AI-8](AI-8-vector-index.md) 에서 함께 처리한다
- **안전 유의사항(`safety`)** — 원자료가 아직 없다. 출처를 정하는 것이 먼저다
- **시설(`facility`)** — 포함 여부가 미정이다 (`../04` §6 ③)
