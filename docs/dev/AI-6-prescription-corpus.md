# AI-6 · 처방 어휘와 처방 청크

코퍼스의 주축을 만든다. 규약은 `../04` §1·§2.

**운동처방 텍스트는 별도 API가 아니라 측정 데이터의 처방 컬럼에 이미 들어 있다**
(`../04` §1). 새로 받을 원자료가 없다 — [AI-1](AI-1-age-band-distribution.md) 이 읽는
그 CSV의 `MVM_PRSCRPTN_CN` 이다.

---

## 1. 두 가지 산출물

같은 원문에서 성격이 다른 둘이 나온다. **나누는 이유는 쓰는 곳이 다르기 때문이다.**

| 산출물 | 무엇 | 쓰는 곳 |
|---|---|---|
| **처방 어휘** | 운동명 641개의 닫힌 집합 | `../03` §4.1 `exercise_names` 의 허용 집합, §5.7 `sessions[].exercise_name` |
| **처방 청크** | `(연령구간, 나이, 성별, 단계)` 한 칸 = 청크 1개 | 검색 대상 (`../04` §1.1) |

어휘는 **닫힌 집합**이다. `../03` §4.1 이 "어휘 밖 문자열은 무시된다"고 정했으므로
그 집합이 파일로 있어야 한다. 청크는 검색되는 문서다.

## 2. 원문의 모양 — 25개월 전수에서 잰 것

| | |
|---|---|
| 전체 행 | 670,546 |
| 처방문이 있는 행 | **630,531 (94.0%)** |
| 고유 처방문 | 308,698 — 그중 **81% 가 한 번만 나온다** |
| 단계 | **정확히 셋** — `준비운동` · `본운동` · `정리운동` |
| 운동명 (원문 그대로) | 645 |
| 운동명 (표기 차이를 합친 뒤) | **641** |

처방문은 이 모양이다.

```
준비운동:등 대고 대퇴이두근 스트레칭,종아리 스트레칭 / 본운동:짐볼에서 몸통 돌리기,… / 정리운동:…
```

- 단계는 ` / ` (앞뒤 공백 포함)로 가른다. 운동명 안에 `/` 가 들어 있어서
  (`가슴/어깨 스트레칭`, `목 굽힘/ 폄 I`) 공백 없는 `/` 로 가르면 이름이 쪼개진다
- 단계 안의 운동은 `,` 로 가른다
- **세 단계가 같은 어휘를 쓴다** — 단계마다 640개 안팎이다. 단계별 어휘를 따로 두지 않는다

> `../04` §1 의 옛 수치(표본 301행 중 87% · 어휘 638개)는 표본에서 잰 값이었다. 전수로
> 다시 쟀다. 638은 재현되지 않는다 — 거기까지 줄이려면 §4 ② 가 금지하는 의미 병합이
> 필요하다.

## 3. 실행

```bash
python -m family_fitness_ai.rag.prescription --data-dir ~/받은자료/kspo-measure
```

원자료를 읽는 두 번째 경로다. `ingest/measurements.py` 의 `load_dir` 는 점수 대상
연령대만 남기는데, **처방 코퍼스는 어르신도 쓴다** — 어르신은 점수·등급을 내지 않을 뿐
질의응답은 정상 동작한다 (`../02` §6 ⑦). 그래서 처방 컬럼만 읽는 적재를 따로 둔다.

## 4. 미결을 정한 것

### ① `일련` — 해시를 쓰지 않는다. `단계` 다

**청크가 칸·단계 집계이므로 `natural_key` 가 전부 구조로 정해진다** (`../04` §1.1).

```
prescription:{연령구간}-{나이}-{성별}-{단계}
prescription:유소년-11-F-본운동
```

**해시보다 낫다.** 원자료가 쌓이면 빈도가 바뀌어 내용 해시가 바뀌고, 그때마다 저장된
인용이 끊긴다. 구조 키는 재수집해도 같은 칸이면 같은 id 다 — `../04` §5 의 "같은
`chunk_id` 로 upsert, `corpus_version` 갱신" 이 정확히 이 경우다.

### ② 운동명 정규화 — 표기 차이까지만 합친다

**NFKC 정규화 뒤 공백·가운뎃점을 지우고 비교한다. 그 이상은 합치지 않는다.**

이 규칙이 합치는 것은 넷이고 전부 띄어쓰기다.

| 합쳐지는 표기 | 건수 |
|---|---|
| `팔굽혀펴기` · `팔굽혀 펴기` | 39,587 · 2,350 |
| `팔벌려뛰기` · `팔 벌려 뛰기` | 22,421 · 1,319 |
| `윗몸 말아 올리기` · `윗몸말아올리기` | 37,599 · 6,461 |
| `배스트레칭` · `배 스트레칭` | 38,252 · 645 |

**비슷해 보이는 이름은 대부분 다른 운동이다.** 유사도로 합치면 틀린다.

| 비슷하지만 다르다 | 이유 |
|---|---|
| `대퇴이두근 스트레칭` · `대퇴이두근 스트레칭2` | 번호가 붙은 별개 동작 |
| `누워서 배가로근 수축 I` · `II` · `목 굽힘/ 폄 I`·`II`·`III` | 단계(난이도) |
| `의자 잡고 전방으로 무릎 굽혀 들기` · `후방으로` | 방향 |

**대표 표기는 가장 많이 쓰인 원문이다** — `팔굽혀펴기` 가 계약의 값이 된다. 나머지
표기는 `raw_forms` 에 남긴다 (`../02` §4 — 원본 문자열을 버리지 않는다).

> `누워 다리 들어올리기` · `누워서 다리 들어올리기` 는 같은 운동으로 보이지만
> 조사 차이라 이 규칙이 합치지 않는다. 사람이 판단할 몫이라 합치지 않고 둔다 (§8 ②).

### ③ 요인 — 비워 둔다

**처방문에 요인이 없다.** 641개 운동에 요인을 붙이려면 사람이 표를 만들거나 통계로
추론해야 하고, 둘 다 판단이 들어간다. 판단 없이 채울 수 있는 값이 아니다.

**비워도 색인은 된다.** 청크 본문에 운동명이 있고, coach 는 "유연성을 키우는 운동"
같은 질의를 텍스트 유사도로 찾는다.

**이후 적용 — 데이터로 추론하는 길이 있다.** 공단의 본운동은 그 사람의 약점 요인을
겨냥해 처방된다고 보면, 특정 요인이 낮은 사람에게 유독 많이 나오는 운동이 그 요인의
운동이다. 측정값과 처방이 같은 행에 있어 계산할 수 있다. 그 가정을 검증한 뒤에 붙인다.

## 5. 산출물

### `data/release/exercise_vocabulary.csv` — 처방 어휘

`data/release/` 에 커밋한다. 계약이 참조하는 닫힌 집합이라 코드와 함께 버전이
움직여야 한다.

| 열 | 내용 |
|---|---|
| `exercise_name` | 대표 표기. **이것이 계약의 값이다** |
| `raw_forms` | 원자료에 나타난 표기 전부. 세미콜론 구분 (`../02` §4) |
| `count` | 전수에서 처방된 횟수 |
| `phases` | 나타난 단계. 세미콜론 구분 |
| `age_groups` | 나타난 연령대. 세미콜론 구분 |
| `fitness_factors` | 비어 있다 — §4 ③ |

### `data/interim/prescription_chunks.csv` — 처방 청크

커밋하지 않는다 (`../02` §4). 색인의 입력이다.

| 열 | 내용 |
|---|---|
| `chunk_id` | `prescription:{연령구간}-{나이}-{성별}-{단계}` |
| `source` | 고정값 `prescription` |
| `text` | 그 칸·단계에서 처방된 운동을 빈도순으로. 비율을 함께 적는다 |
| `citation_label` | `국민체력100 운동처방 · {연령구간} {나이}{세·개월}` |
| `citation_url` | 비어 있다 |
| `age_group` · `age` · `age_unit` · `sex` · `phase` | 필터 값 (`../04` §2.2) |
| `n` | 그 칸의 처방 행 수 |
| `exercise_names` | 본문에 실린 운동. 세미콜론 구분 |

**본문은 처방 누적 80% 를 덮을 때까지 싣는다 (최대 30개).** 한 칸·단계에 서로 다른
운동이 중앙 102개 · 최대 342개라 전부 실으면 `../04` §2.1 의 400토큰을 넘는다. 상위
운동이 빠르게 덮는다 — 유소년 여 11세 정리운동은 상위 17개가 80% 다.

**상한이 30개인 근거** (2026-09-16) — 임베딩 모델이 `bge-m3` 로 정해져 토크나이저가
생겼다 ([AI-8](AI-8-vector-index.md) §1.3). 그 토크나이저로 재니 운동 30개까지는
최대 369토큰이고, 40개까지 실으면 495토큰으로 규약을 넘었다.

**유아기는 `개월` 이다** (`../02` §2.4). 인용 문자열도 `유아기 60개월` 로 적는다.

## 6. 정제

### 6.1 표본 30 미만인 칸은 청크를 만들지 않는다

프로젝트 전체의 저표본 기준(`../02` §5.3)을 따른다. 30명도 안 되는 칸의 "많이 처방된
운동" 은 우연과 구분되지 않는다. 걸리는 칸은 **91세 이상 어르신뿐**이다.

같은 연령대의 다른 칸이 연령 필터를 통과하므로 그 사람의 질의가 비지 않는다 —
필터는 나이가 아니라 연령대로 걸린다 (`../04` §3).

### 6.2 만 120세 초과는 측정 오류로 본다

어르신 나이에 `377` · `378` · `984` · `1071` · `1081` 이 있다. 실제 최고령은 103세이고
**103과 377 사이가 통째로 비어 있어** 경계를 104~376 어디에 두어도 결과가 같다 — 경계
값에 결과가 기대지 않는다. `../02` §2.5 의 정제와 같은 성격이다.
