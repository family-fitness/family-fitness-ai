# AI-8 · 임베딩 · 색인 · 검색

청크를 벡터로 바꾸고, 색인하고, 연령 필터가 걸린 검색을 낸다. 규약은 `../04` §2·§3·§5.

**저장 위치는 `vector_store` 가 아니라 백엔드의 `ai_documents` 다.**
`../01` §4.1 의 스키마는 우리가 제안한 것이고, 실제로 서는 것은
`family-fitness-be` 의 `docs/erd.dbml` 이다 —
대조는 [AI-13](AI-13-backend-contract-reconciliation.md) §3.3·§3.4.

---

## 1. 저장소는 우리 것이다

**백엔드 ERD에서 `ai_documents` 표가 없어졌다** (19표 → 18표). 벡터 저장소를 우리가
온전히 소유한다 ([AI-13](AI-13-backend-contract-reconciliation.md) §3.3).

| 항목 | 상태 |
|---|---|
| 스키마 | **우리가 정한다** — `../01` §4.1 의 `vector_store` |
| 임베딩 모델·차원 | **우리가 고른다.** 백엔드 문서에 언급이 없다 |
| 인용 전달 | `coach_message_citations.chunk_id varchar(200)` 에 우리 문자열이 그대로 담긴다 |
| 백엔드 접근 | 없다. 아무도 우리 행을 건드리지 않는다 |

**이 갈래를 막던 둘이 문제 자체로 사라졌다.** 연령 상한 컬럼과 결정적 `chunk_id` 를
백엔드에 요청할 이유가 없어졌다 — 둘 다 우리 스키마의 일이다.

### 1.1 대신 두 규약이 홀로 선다

기댈 외부 제약이 없다는 뜻이기도 하다.

- **연령 안전** (`../04` §3) — `WHERE` 절에 필터가 있어야 한다. 백업이 없다
- **`chunk_id` 결정성** (`../04` §1) — 재색인 때 같은 원문이 같은 id 를 갖는 것을
  강제할 제약이 없다. **색인 코드가 그 불변식을 검사한다** (§3.1)

### 1.2 FAISS 는 폴백이 아니라 로컬 개발용이다

`../01` §1 은 "DB가 서기 전에도 개발이 멈추지 않게" FAISS를 두었다. 저장소가 우리
것이 됐으므로 배포 기본값은 `pgvector` 이고 FAISS는 로컬 전용이다. `VECTOR_BACKEND`
는 남긴다 — 호출부가 같아야 한다는 이유는 그대로다.

## 2. 청크를 모은다

| `source` | 어디서 | 상태 |
|---|---|---|
| `prescription` | [AI-6](AI-6-prescription-corpus.md) | 이 갈래에서 만든다 |
| `video` | [AI-7](AI-7-video-labeling.md) | 이 갈래에서 만든다 |
| `criteria` | `data/release/grade_thresholds.csv` | **이미 있다.** 여기서 청크로 편다 |
| `safety` | 원자료 미정 | 넣지 않는다 |
| `facility` | 포함 여부 미정 (`../04` §6 ③) | 넣지 않는다 |

**우리 `source` 5종과 `ai_documents.document_kind` 의 값 집합을 맞춰야 한다.**
ERD 주석의 예시는 `GUIDE`·`VIDEO_CAPTION` 이다. 어느 쪽 어휘를 쓸지는
[AI-13](AI-13-backend-contract-reconciliation.md) 의 합의에 붙인다.

**`criteria` 청크는 연령 무관이다** (`../04` §2.2). 청크의 연령 값은 "이 자료를
누구에게 보여도 되는가"이지 "누구에 관한 자료인가"가 아니다.

## 3. 색인

```bash
python -m family_fitness_ai.rag.index --corpus-version 2026-09-15.1
```

배치 태스크만 색인한다. **온라인 요청 처리 중에 코퍼스가 바뀌지 않는다**
(`../01` §4.2 · `../04` §5).

### 3.1 색인 전 검사 — 통과하지 못하면 색인하지 않는다

| 검사 | 왜 |
|---|---|
| `prescription`·`video` 청크의 연령이 비어 있지 않다 | `../04` §2.2. 이 검사가 "연령 무관"을 안전하게 만드는 짝이다 |
| `natural_key` 가 내용에서만 나왔다 | `../04` §1. 순번·수집 시각을 쓰지 않는다 |
| 같은 내용이 같은 행으로 upsert된다 | §2.2 |
| 청크 길이가 50~400토큰 | `../04` §2.1 |

**빠뜨린 것을 세어 보고한다.** 조용히 거르면 코퍼스가 왜 작은지 알 수 없다.

### 3.2 재색인

`../04` §5 의 표를 따른다. **원자료가 같으면 같은 행을 갱신한다.**

**청킹 규칙을 바꿀 때는 저장된 인용의 대응이 깨지는지 먼저 확인한다.** 사라진
식별자가 있으면 그것을 참조하는 `coach_message_citations.ai_document_id` 가 끊긴다.

`corpus_version` 과 `embedding_version` 은 다른 것이다 — 앞은 코퍼스를 다시 만든
횟수고 뒤는 임베딩 모델의 판이다. `ai_documents` 에는 뒤만 있다.

## 4. 검색

`../04` §3 의 표를 그대로 옮긴다.

| 항목 | 값 |
|---|---|
| 1차 top-k | 10 |
| 최종 컨텍스트 | 최대 5청크 |
| 임계값 | `SIM_THRESHOLD` |
| 연령 필터 | **항상.** 상·하한 둘 다 (§2.1이 풀린 뒤) |
| 공간·소음·기구 | **받는다** — [AI-9](AI-9-videos-search.md) §1 |

**연령 필터를 끄는 인자를 만들지 않는다.** 인자가 있으면 언젠가 꺼진다.

**임계값은 `WHERE` 절에 있고 정렬 뒤의 후처리가 아니다** (`../04` §3). 후처리로
거르면 "0건인데 LLM을 호출하는" 경로가 생긴다. pgvector에는 `WHERE` 가 있고
FAISS에는 없으므로, **검색 인터페이스가 (결과, 제외 사유별 건수)를 함께 돌려주게
해서 두 백엔드가 같은 모양을 내게 한다.** `../03` §4.2 의 `filtered_out` 이 이 값이다.

## 5. `SIM_THRESHOLD` 를 잰다

`../04` §6 ② 가 미결이고 **기본값이 없다** — 값이 없으면 `/readyz` 가 실패해 서비스가
요청을 받지 않는다 ([AI-3](AI-3-service-skeleton.md) §2.1).

**임의의 숫자를 하드코딩하지 않는다** (`../04` §3). 근거 없는 임계값은 조용히 관련
자료를 버린다.

1. **질의 세트를 손으로 만든다.** 연령대·요인을 고르게 섞은 30~50개
2. 각 질의에 대해 관련·무관 청크를 사람이 표시한다
3. 두 집합의 유사도 분포를 그린다
4. 경계를 잡고 **그 근거와 함께** 설정에 상수로 남긴다

| 산출 | 내용 |
|---|---|
| `data/interim/sim_eval.csv` | 질의 × 청크 × 유사도 × 사람이 붙인 관련 여부 |
| 리포트 | 임계값 후보별 정밀도·재현율, 고른 값과 그 이유 |

**질의 세트는 커밋한다.** 임베딩 모델이 바뀌면 임계값을 다시 재야 하고, 그때 같은
질의로 재야 비교가 된다.
