# AI 서비스 계약

AI 서비스(FastAPI)가 내야 하는 것 전부다. 기준 경로 `/v1`, JSON(UTF-8), 인증 없음.

## 공통

**오류** — 실패는 한 모양이다. 성공은 payload 를 그대로 낸다(봉투 없음).

```json
{"error": {"code": "RUN_IN_PROGRESS", "message": "실행 중인 코치 실행이 있습니다"}}
```

| 상태 | `code` | 조건 |
|---|---|---|
| `400` | `BAD_REQUEST` | 필수 필드 누락·타입 불일치 |
| `400` | `ITEM_NOT_ALLOWED` | `measurements` 에 `005`·`006`(혈압) |
| `404` | `RUN_NOT_FOUND` | `run_id` 없음 |
| `404` | `NOT_FOUND` | 그런 경로가 없음 |
| `405` | `METHOD_NOT_ALLOWED` | 그 경로가 받지 않는 메서드 |
| `409` | `RUN_IN_PROGRESS` | 같은 프로필에 실행 중인 run |
| `503` | `TEMPORARILY_UNAVAILABLE` | LLM·인덱스 장애 |

**거부는 오류가 아니다.** `refused: true` 는 HTTP `200` 이다.

`GET /coach/runs/{run_id}` 를 `run_id` 없이 부르면 `/coach/runs` 로 슬래시가 정리되어 `405` 가 된다. 응답의 `run_id` 는 **snake_case** 다.

**응답 시간** — 호출자가 끊는 시각이다. 넘기면 503 과 같다.

| 엔드포인트 | 한도 |
|---|---|
| `/fitness/assessment` · `/fitness/trajectory` | 3s |
| `/videos/search` | 4s |
| `/coach/messages` | 10s |
| `POST /coach/runs` | 2s |
| `GET /coach/runs/{run_id}` | 3s · 1.5s 간격 40회 폴링 → **60s 안에 끝난다** |

**타입**

| 이름 | 값 |
|---|---|
| `Sex` | `M` · `F` |
| `AgeUnit` | `세` · `개월` — 유아기만 `개월` |
| `AgeGroup` | `유아기` · `유소년` · `청소년` · `성인` · `어르신` |
| `InputLevel` | `L0`(나이·성별) · `L1`(+신장·체중) · `L2`(+측정값) |
| `FitnessFactor` | `심폐지구력` · `근력` · `근지구력` · `유연성` · `민첩성` · `순발력` · `협응력` · `평형성` |
| `Band` | `strength`(백분위≥75) · `steady`(25~75) · `growth`(<25) · `null`(미측정) |
| `Role` | `주행자` · `동반자` · `응원` |
| `Citation` | `{index, label, chunk_id, url?}` |

**보내지 않는 것** — 이름·생년월일·연락처. 프로필은 `profile_ref` 로만.

**문구** — `band`·`factor` 같은 코드값은 화면에 나가지 않는다. 표시 문구는 `copy`·`disclaimer`·`notice` 로 따로 낸다. "부족"·"미달"·"하위"를 쓰지 않는다.

## 1. `POST /fitness/assessment`

측정값을 또래 분포와 대조해 요인별 점수로 바꾼다. **측정값이 없어도 `200`** 이다.

**요청**

```json
{"profile_ref": "p_c7a91f", "age": 11, "age_unit": "세", "sex": "F",
 "height_cm": 148.0, "weight_kg": 41.0,
 "measurements": {"028": 41.3, "012": 4.0, "020": 70, "022": 133, "009": 30}}
```

`height_cm`·`weight_kg` 는 `null` 일 수 있고 `measurements` 는 `{}` 일 수 있다.

**응답**

```json
{
  "input_level": "L2",
  "age_group": "유소년",
  "child_scope": {"focus_one": {"factor": "순발력", "copy": "이번 주는 힘껏 뛰어오르는 동작을 해볼까요"}},
  "parent_scope": {
    "grade": "3등급",
    "peer_distribution": [{"grade": "1등급", "ratio": 0.0322}],
    "factors": [
      {"factor": "심폐지구력", "item_code": "020", "item_name": "왕복오래달리기",
       "item_label": "15m왕복오래달리기", "unit": "회",
       "value": 70.0, "score": 85.9, "percentile": 80, "band": "strength", "n": 28215}
    ],
    "copy": {"strength": "심폐지구력은 잘하고 있는 영역입니다", "focus": "순발력은 꾸준히 하고 있는 영역입니다"}
  },
  "low_sample": false,
  "disclaimer": "국민체력100 측정 데이터를 바탕으로 한 참고 정보입니다. 질병의 진단·치료를 위한 것이 아니며, 건강에 관한 판단은 전문가와 상담하세요."
}
```

| 규칙 | |
|---|---|
| `L0`·`L1` | `focus_one` 은 `null`, `factors` 는 빈 배열, `grade` 는 `null` |
| `score` | 0~100. 미측정·표본부족이면 `null` — **0이 아니다** |
| `n < 30` | `score`·`percentile` 을 `null` 로 내리고 `low_sample: true` |
| `grade` | `1등급` · `2등급` · `3등급` · `참가` · `null` |
| `item_label` | 그 연령대의 실제 시험명. `020` 이 유소년은 15m, 청소년·성인은 20m 다 |

**`percentile` 과 `score` 는 다른 값이다.** `percentile` 은 또래 중 실제 자리다 — 같은 값이 잔뜩 몰린 항목(벽패스처럼 0이 많은 것)에서 순위가 확 튀지 않도록 아래 자리와 위 자리의 가운데를 쓴다. `score` 는 그 자리를 또래 평균·표준편차로 매끄럽게 편 0~100 눈금이라, 값이 조금 오르면 점수도 조금 오른다. 화면의 막대는 `score`, 「상위 몇 %」는 `percentile` 이다.

**등급은 다 재야 나온다.** 한 등급으로 인증하려면 그 등급이 보는 항목을 전부 재고 전부 충족해야 한다. 하나라도 안 쟀으면 `null` 이다 — 집에서 두어 개만 잰 사람을 맨 아래로 내리지 않으려는 것이다. 전부 쟀는데 못 미치면 `참가`. 유소년 인증 기준표는 11~12세만 있어 그 아래 나이는 `null` 이 된다.

**측정값이 없으면 요인을 지목하지 않는다.** 근거 없이 고른 요인에는 인용할 것이 없다.

`band` 문구 — `strength` "잘하고 있는 영역" · `steady` "꾸준히 하고 있는 영역" · `growth` "지금 키우기 좋은 영역".

## 2. `POST /fitness/trajectory`

또래 집단이 연령을 따라 보이는 분포다. 개인의 미래가 아니다.

**요청** — assessment 와 같고 `item_code`(기본 `028`) · `horizon_years`(1~10, 기본 10) 가 붙는다.

**응답**

```json
{
  "basis": "cross_sectional_group_distribution",
  "item_code": "028", "item_name": "상대악력", "unit": "%",
  "bands": [{"age": 11, "p10": 30.2, "p50": 41.3, "p90": 53.3, "n": 28312}],
  "notice": "집단 분포를 바탕으로 한 참고 범위입니다. 개인의 변화를 나타내지 않습니다.",
  "low_sample": false
}
```

`predict`·`forecast` 계열 이름을 두지 않는다.

## 3. `POST /videos/search`

처방 운동명이나 체력 요인으로 운동영상을 찾아 근거와 함께 돌려준다. **한 요청에서 두
곳을 함께 찾는다** — 유튜브 운동영상(임베딩 검색)과 공단 국민체력100 동영상(공공데이터
API 로 받아 둔 표에서 이름·요인·연령대로). 어느 쪽인지는 `source` 로 가른다.

**요청**

```json
{"age_group": "유소년", "fitness_factors": ["유연성"],
 "exercise_names": ["다리 벌려 앞으로 상체 숙이기"], "k": 5}
```

`age_group` 은 필수다. `fitness_factors` 와 `exercise_names` 중 최소 하나는 있어야 한다. `어르신` 은 `성인` 영상도 함께 찾는다(공단 「공통」 영상 포함) — 어르신 전용 영상을 따로 두지 않는다.

**응답**

```json
{
  "hits": [
    {"source": "kspo", "video_id": "0AUDLJ08S_00414",
     "url": "https://openapi.kspo.or.kr/web/video/0AUDLJ08S_00414.mp4",
     "start_sec": 0, "end_sec": 103, "score": 0.9,
     "matched_exercise_names": ["다리 벌려 앞으로 상체 숙이기"],
     "citation": {"label": "국민체력100 운동처방가이드 · 다리 벌려 앞으로 상체 숙이기", "chunk_id": "kspo:0AUDLJ08S_00414"}},
    {"source": "youtube", "video_id": "IdpXx2gm90o",
     "url": "https://www.youtube.com/watch?v=IdpXx2gm90o&t=0s",
     "start_sec": 0, "end_sec": null, "score": 0.68,
     "matched_exercise_names": [],
     "citation": {"label": "국민체력100 운동영상 · 초등학생의 기초체력향상…", "chunk_id": "video:IdpXx2gm90o"}}
  ],
  "filtered_out": {"age_group": 3, "below_threshold": 5}
}
```

`hits` 는 **0건일 수 있다.** 연령 라벨이 없는 영상이 많아 아이 프로필 검색은 자주 빈다. 결함이 아니다.

| 자리 | 뜻 |
|---|---|
| `source` | `youtube` · `kspo`. 트는 쪽이 다르다 |
| `url` | 틀 주소. 유튜브는 `watch?v=<id>&t=<start_sec>s`, 공단은 영상 파일(https) |
| `start_sec` · `end_sec` | 여기부터 여기까지 튼다. 공단은 한 편이 한 동작이라 `0` ~ 영상 길이다. 유튜브는 요청한 운동명이 그 영상에 있으면 그 클립의 시각이고, 없으면 `0` 에서 열고 `end_sec` 은 `null`(끝을 모른다) |
| `score` | 0.0~1.0. 유튜브는 임베딩 유사도, 공단은 표에서 맞은 정도 — 이름·요인 둘 다 `0.9` · 이름만 `0.8` · 요인만 `0.6`. 요인 점수(0~100)와 다른 값이다 |
| `citation.chunk_id` | 유튜브 `video:<id>`, 공단 `kspo:<video_id>` |

유튜브는 체력 요인만으로 찾으면 운동명이 없어 영상을 처음부터 연다(`start_sec` `0`,
`end_sec` `null`). 공단은 늘 한 동작짜리 클립이다. 공단에는 유아기 영상이 없다 — API 에는
있으나 공단 서버에 파일이 없다.

## 4. `POST /coach/runs` · `GET /coach/runs/{run_id}`

한 주 분량의 미션을 편성해 **제안**한다. 15~40초가 걸려 비동기다.

**요청**

```json
{
  "profile_refs": [
    {"ref": "p_c7a91f", "role": "주행자", "age": 11, "age_unit": "세", "sex": "F",
     "input_level": "L2", "height_cm": null, "weight_kg": null, "measurements": {"028": 41.3}},
    {"ref": "p_3d0b25", "role": "동반자", "age": 41, "age_unit": "세", "sex": "F",
     "input_level": "L1", "height_cm": 162.0, "weight_kg": 57.0, "measurements": null}
  ],
  "period": {"start_date": "2026-09-07", "weeks": 1},
  "constraints": {"days_per_week": 3, "minutes_per_session": 15, "weekly_minutes": 30,
                  "quiet": false, "small_space": false, "no_props": false,
                  "focus_factor": "유연성", "with_companion": false}
}
```

`constraints` — 일간은 `days_per_week`(1~7)와 `minutes_per_session`(5~60), 주간은 `weekly_minutes`(5~90)다. `weekly_minutes` 를 비우면 주간 미션을 만들지 않는다. `quiet`(뛰는 동작을 뺀다) · `small_space`(좁은 데서 되는 것만) · `no_props`(도구 없이)는 기본이 `false` 고, 켠 것만 좁힌다.

`focus_factor` 는 **보호자가 키워 주고 싶은 역량**이다. 여덟 요인의 한글 이름(`심폐지구력` · `근력` · `근지구력` · `유연성` · `민첩성` · `순발력` · `협응력` · `평형성`) 가운데 하나거나 `null` 이다. 있으면 측정으로 고른 가장 낮은 요인 대신 이 요인으로 처방을 찾고 클립을 고른다 — 규칙 편성이든 LLM 편성이든 같다. 그 요인을 쟀으면 백분위도 함께 보고, 안 쟀어도 이 요인으로 짠다. 이 요인은 일간을 받는 사람(주행자, 없으면 첫 사람) 몫이고 동반자에게는 걸지 않는다. `null` 이나 빈 글자면 전처럼 측정으로 고르고, 목록에 없는 이름은 `400 BAD_REQUEST` 다. 그 나이에 이 요인 처방이 없으면 다른 처방처럼 넓혀서 고르고 `notices` 에 적는다.

`with_companion` 은 보호자도 같이 하는지다(기본 `false`). 참여자를 늘리지는 않는다 — 같이 할 사람은 `profile_refs` 에 넣는다. LLM 편성일 때 코치에게 알려 아이 문구에 반영할 뿐이고, 규칙 편성에는 영향이 없다.

**일간과 주간은 다르다.**

| | 일간 | 주간 |
|---|---|---|
| 몇 건 | `days_per_week` 만큼 | 한 건 |
| 기간 | 하루 (`start_date` = `end_date`) | 그 주 전체. **날짜를 정하지 않는다** |
| 참여 | 주행자 (+ `응원`) | 주행자 · 동반자 (+ `응원`) |
| 길이 | `minutes_per_session` | `weekly_minutes` |

`동반자` 는 제 몫의 일간을 받지 않는다. 주간에 함께하는 사람이다.

`profile_refs` 1~4명. `응원` 은 편성 대상에서 빠지고 참여자로만 기록된다.

**응답 `202`** — `{"run_id": "cr_…", "status": "running", "poll_after_ms": 1500}`

**응답 `200` (GET)**

```json
{
  "run_id": "cr_01J7Q3M8VZ2K",
  "status": "succeeded",
  "steps": [
    {"seq": 1, "name": "assess",   "status": "ok", "summary": "유연성 백분위 24 · 대상 요인 = 유연성"},
    {"seq": 2, "name": "retrieve", "status": "ok", "summary": "처방 청크 6건 · 클립 후보 488개"},
    {"seq": 3, "name": "compose",  "status": "ok", "summary": "미션 3건 · 클립 38개 · 코치가 편성"},
    {"seq": 4, "name": "verify",   "status": "ok", "summary": "인용 2건 · 금지 어휘 0건"}
  ],
  "proposal": {
    "missions": [
      {
        "kind": "일간",
        "title": "월요일 늘이기",
        "period": {"start_date": "2026-09-07", "end_date": "2026-09-07"},
        "participants": [{"ref": "p_c7a91f", "role": "주행자"}],
        "duration_min": 15,
        "video_sec": 418,
        "sessions": [
          {"day_offset": 0, "phase": "준비운동", "order": 1,
           "exercise_name": "넙다리 안쪽 늘리기 (나비자세)", "fitness_factor": "유연성",
           "duration_sec": 38,
           "video": {"source": "youtube", "video_id": "Eg3GpTv7z8s",
                     "url": "https://www.youtube.com/watch?v=Eg3GpTv7z8s&t=144s",
                     "start_sec": 144, "end_sec": 182},
           "evidence": [1, 2]}
        ],
        "copy": {"child": "이번 주는 몸을 길게 늘이는 동작, 엄마랑 같이 해볼까요",
                 "parent": "유연성은 지금 키우기 좋은 영역입니다. 주 3회 15분이면 충분합니다"},
        "reason": "또래 처방에 나온 늘이는 동작을 앞세워 골랐습니다 [1]."
      }
    ],
    "citations": [
      {"index": 1, "label": "국민체력100 운동처방 · 유소년 11세", "chunk_id": "prescription:유소년-11-F-0142"}
    ],
    "notices": []
  },
  "refused": false,
  "refusal_reason": null
}
```

`status` — `running` · `succeeded` · `failed` · `refused`. `proposal` 은 `succeeded` 일 때만 찬다.

`steps[].name` 은 `assess` · `retrieve` · `compose` · `verify` 넷. `status` 는 `ok` · `partial` · `failed`. `focus_factor` 를 보냈으면 `assess` 의 `summary` 가 `평형성 측정값 없음 · 대상 요인 = 평형성(보호자가 고름)` 처럼 나간다.

코치(LLM)가 짠 편성은 받은 뒤 규칙으로 손본다 — 모자란 편수를 목록에서 채우고, 한 주 안에서 이미 쓴 동작은 바꾸고, 규칙에 어긋난 글은 그 칸만 규칙 문구로 바꾼다. 손본 만큼은 `compose` 의 `summary` 끝에 「목록에서 n편 채움 · 문구 n칸 규칙으로」로 붙는다(손본 것이 없으면 붙지 않는다). 미션은 일간이 날짜순이고 주간이 맨 뒤다.

**미션 하나가 하루다.** `sessions` 는 그날 순서대로 이어 하는 **클립**이고, `phase` 가 `준비운동` → `본운동` → `정리운동` 순으로 놓인다. 유튜브 영상은 한 편에 운동이 여럿 들어 있어 통째로 내보내면 아이가 기다린다. 그래서 화면에 뜨는 운동 이름이 바뀌는 지점마다 끊어 둔다. 공단 동영상은 처음부터 한 편이 한 동작이라 끊지 않는다 — `start_sec` 은 `0`, `end_sec` 은 영상 길이다. 두 곳의 클립은 한 목록에서 똑같이 고른다.

**클립 길이의 합은 `duration_min` 과 다르다.** 한 편을 여러 세트 반복해 시간을 채우는 것은 화면 쪽 몫이고, 우리는 **가짓수**를 낸다 — 15분이면 7편(준비 2 · 본 4 · 정리 1), 30분이면 9편이다. 영상 길이를 다 합쳐 요청 시간에 맞추면 30~40초짜리가 스무 편씩 붙어 따라 할 수 없는 목록이 된다.

| 자리 | 뜻 |
|---|---|
| `sessions[].phase` | `준비운동` · `본운동` · `정리운동` |
| `sessions[].order` | 그날 안에서의 차례 (1부터) |
| `sessions[].duration_sec` | 그 클립 길이. 분이 아니라 초다 |
| `sessions[].video.end_sec` | 클립이 끝나는 시각. `start_sec` 부터 여기까지만 튼다 |
| `sessions[].video.source` | `youtube` · `kspo`(공단 국민체력100 동영상) |
| `sessions[].video.url` | 틀 주소. 유튜브는 `watch?v=<id>&t=<start_sec>s`, 공단은 영상 파일(https) |
| `citations[].chunk_id` · `url` | 공단 영상을 근거로 든 인용은 `kspo:<video_id>` 이고 `url` 에 영상 주소가 온다 |
| `missions[].kind` | `일간` · `주간` |
| `missions[].duration_min` | 그 회 운동 시간. 요청한 `minutes_per_session` 이나 `weekly_minutes` 다 |
| `missions[].video_sec` | 그날 클립 길이의 합(초). `duration_min` 과 다르다 |
| `missions[].reason` | 왜 이렇게 짰는지. 본문에 `[n]` 이 박힌다 |
| `proposal.notices` | 또래 자료가 없어 넓혀 골랐을 때의 알림. 빈 배열일 수 있다 |

**없으면 넓혀서 권하고, 넓혔다고 말한다.** 국민체력100 처방은 나이 한 살 단위로 나뉘어 있고 모든 나이가 차 있지 않다. 만 8세 자리가 비었다고 빈손으로 돌려보내지 않는다 — 같은 연령대, 같은 성별, 그래도 없으면 연령대 밖으로 한 칸씩 넓히고 `notices` 에 적는다. 영상도 같다. 연령 라벨이 붙은 편이 많지 않아 또래만 고집하면 아이에게 줄 것이 없다. 라벨이 다른 영상이 섞이면 그 사실을 알리고, 쓸지는 화면 저쪽에서 정한다.

**강등과 거부**

| 상황 | 동작 |
|---|---|
| 그 나이 처방이 없다 | 연령대·성별·요인 순으로 넓히고 `notices` 에 적는다 |
| 또래 연령 영상이 적다 | 다른 연령대 영상도 후보에 넣고 `notices` 에 적는다 |
| 어르신(65세 이상) | 성인 영상(공단 「공통」 포함)을 또래로 친다 — 규칙 편성도 성인 클립으로 짜고, `notices` 에 적지 않는다 |
| LLM 이 실패한다 | 규칙 편성으로 계속. `compose` 가 `partial` 이 된다 (인용 유지) |
| **인용이 0이다** | **거부.** `proposal` 은 `null` |

`verify` 는 반환 직전에 셋을 본다 — 인용 1개 이상, 본문 `[n]` 과 `evidence` 가 인용 범위 안, 금지 어휘 없음. 부분 통과는 없다. 연령대가 다른 영상은 막지 않는다. 막으면 자료가 얇은 연령대는 아무것도 못 받는다 — 대신 `notices` 로 알린다.

**LLM 은 편성을 맡고, 고를 수 있는 것은 우리가 준다.** 어떤 클립이 후보인지, 어떤 처방이 근거인지는 검색과 표가 정해서 넘긴다. LLM 은 그 안에서 고르고 순서를 잡고 문구를 쓴다. 목록에 없는 id 를 지어내면 그 자리는 버려진다. 부르지 못하거나 답이 규칙에 어긋나면 규칙 편성이 대신 선다.

**AI 는 DB 에 쓰지 않는다.** 저장과 승인은 전부 호출자가 한다.

## 5. `POST /coach/messages`

운동·체력 질문에 자료를 검색해 출처를 인용하며 답한다. 자료에 없으면 거부한다.

**요청** — `{"profile_ref": "…", "age_group": "유소년", "question": "1~500자"}`

**응답**

```json
{
  "answer": "또래 유소년 여아 처방에서는 상체를 앞·옆으로 숙이는 준비운동 동작이 함께 제시됩니다 [1].",
  "citations": [{"index": 1, "label": "국민체력100 운동처방 · 유소년 11세", "chunk_id": "prescription:유소년-11-F-0142"}],
  "refused": false,
  "refusal_reason": null
}
```

`answer` 문장 끝에 `[n]` 이 박힌다. `refused=false` 면 `citations` 는 최소 1개다.

`refusal_reason` — `no_relevant_source` · `age_filter_empty` · `medical_query` · `no_citation_generated`.

부상·통증·질환·약물 질의는 **검색조차 하지 않고** `medical_query` 로 거부한다.

**협응력은 연령대마다 다른 시험을 쓴다.** `017` 은 청소년의 계산결과값(초, 작을수록 우수)이고, `044` 는 유소년의 벽패스 성공 횟수(회, 클수록 우수)다. 컬럼정의서는 `044` 를 「(초)」로 적어 두었지만 값은 0~40의 정수이고, 기준표의 유소년 「눈-손 협응력 검사 (회)」와 단위가 맞는다. 원자료에서 둘은 한 줄에 같이 나오지 않는다.

**받지 않는 것** — `005`·`006`(혈압)은 `400 ITEM_NOT_ALLOWED`.

**신체조성은 요인이 아니라 등급의 관문이다.** `003`(체지방률)·`004`(허리둘레)·`018`(BMI)·`042`(WHtR)는 클수록 좋다도 작을수록 좋다도 아니라 적정 구간이 있을 뿐이라, 백분위를 점수로 바꾸지 않는다 — `FitnessFactor` 여덟 중 여기 해당하는 것도 없다. 대신 **3등급 판정에서 민첩성·순발력·협응력 자리를 대신 맡는다.** 기준표 3등급 줄을 보면 운동 체력 칸이 비고 BMI·체지방률·WHtR 칸이 차 있다. `018` 은 안 재도 신장·체중이 있으면 우리가 낸다.
