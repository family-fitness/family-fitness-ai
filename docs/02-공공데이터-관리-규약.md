# 02 · 공공데이터 관리 규약

국민체력100 공공데이터를 **어디서 받아, 어디까지 쓰고, 무엇으로 바꾸는가**를 확정한다.
API 응답에 실리는 값의 뜻은 여기서 정해진다.

앱 화면에 보이는 인용 문자열은 형식이 따로 있다 (`docs/04`).

### 1.1 파일데이터가 주 소스다

월별 CSV가 API 응답의 **상위집합**이다. API 23개 필드 중 21개가 그대로 있고, 빠진
둘(`row_num`·`age_class`)은 조회 순번과 파생값이라 손실이 아니다. 파일에만 있는
컬럼이 5개 더 있다.

| | API | **파일데이터** |
|---|---|---|
| 트래픽 한도 | 1,000회/일 | **없음** |
| 회원 식별자 | 없음 | `MBER_SEQ_NO_VALUE` 있음 |
| 이상치 비율 | ~1% | **0.01~0.02%** |
| 유소년 비중 | 6.8% | **17.1%** (2.5배) |

## 2. 데이터의 모양 — 확인된 사실

### 2.1 연령 구분 값은 다섯 개이고 표기가 비대칭이다

**API 전수 2,937,487건 기준**이다. 다섯 값의 건수 합이 전체와 정확히 일치하므로
이것이 값의 전체 집합이다. (파일데이터 24개월분의 연령대 구성비는 다르다 — )

| 값 | 공식 연령 |
|---|---|---|---|
| `성인` | 만 19~64 |
| `청소년` | 만 13~18 |
| `어르신` | 만 65~ |
| `유소년` | 만 11~12 |
| `유아기` | 만 4~6 (48~83개월) |

> ⚠ **`유아기` 만 '기'가 붙는다.** `유아`·`유소년기`·`청소년기`·`성인기`·`어르신기` 는
> 전부 0건이다. 패턴으로 추론하지 말고 다섯 문자열을 상수로 고정한다.

```python
AGE_GBN = ("유아기", "유소년", "청소년", "성인", "어르신")  # 실측 확정. 변형 금지
```


### 2.4 연령 단위 — 유아기만 개월

`MESURE_AGE_CO` 는 유아기만 개월(48~83)이고 나머지는 세다. 월령 원값도 남긴다 —
등급 기준표가 유아기를 개월 구간으로 나눈다.

### 2.5 정제 규칙

API 응답 표본 301행에서 물리적으로 불가능한 값이 3건 나왔다. 이 표본은 성인·사업
초기(2011~2012년) 데이터에 치우쳐 있어 비율을 전체로 외삽할 수 없다 — 파일데이터의
이상치 비율은 훨씬 낮다 **다만 값이 존재한다는 사실은 확인됐고, 정제 없이
넣으면 꼬리 분위수가 오염된다.**

| 항목 | 관측 이상치 | 허용 범위 (제안) |
|---|---|---|
| 체지방률 | 234.0% | 3~60% |
| 허리둘레 | 1.0cm | 40~150cm |
| 수축기혈압 | 40mmHg | 70~200mmHg |

## 3. 취급 원칙

- **원자료는 커밋하지 않는다.** 재현은 커밋된 수집·산출 스크립트로 한다
- 공공데이터는 비식별이다. **재식별을 시도하는 코드를 작성하지 않는다**
- 공개 산출물은 **라벨 메타데이터로 한정**한다. 영상·프레임·썸네일은 재배포하지 않는다
- 혈압(`005`·`006`)은 수집물에 있어도 **AI 경계 밖**이다. API로 전송받지 않는다
- 체지방률·허리둘레는 내부 보정용이며 **응답에 수치로 나가지 않는다**

### 3.1 원자료 공유와 목록

원자료(월별 CSV 25개, 284MB)는 레포에 들어가지 않는다.
**원자료 요구시 사용자에게 요청한다.**

파일 대신 목록만 커밋한다 — `data/manifest.csv`.

| 열 | 내용 |
|---|---|
| `file` | 파일명 |
| `period` | 대상 연월 `YYYYMM` |
| `rows` | 행 수 |
| `acquired_at` | 취득일 `YYYY-MM-DD` |

`rows` 는 적재하면서 어차피 세는 값이고, 파일이 잘리거나 엉뚱한 달이 섞였을 때
그것을 드러낸다.


**zip 에는 측정 기록과 컬럼정의서만 담는다.** 등급 기준표는 값이 작고 잘 바뀌지
않으므로 `data/release/grade_thresholds.csv` 로 레포에 커밋해 둔다 — 받는 사람은 zip
만 풀면 되고 기준표를 따로 챙기지 않는다.

산출물은 `data/release/` 에 커밋되어 있고 원자료에서 언제든 재생성된다. 실행은
`make distribution DATA_DIR=…` 이고 **저장소 루트에서** 돌린다 (`docs/05`).


### 3.2 YouTube API 사용 제약

- 허용: `playlistItems.list` · `videos.list` · `playlists.list` · `channels.list`
- 라벨링 목적의 프레임 추출은 한 모듈에서만 하고, 시트 생성 후 원본을 지운다
- 금지: 영상·프레임·썸네일 재배포, 원본 재가공 배포
- ⚠ **`search.list` 는 일일 100회 제한**이다. `channels.list` → `playlists.list`
  경로를 쓴다

## 5. 등급 판정 — 공단 기준을 따른다

**공단의 등급 판별만 쓴다.** 우리가 따로 등급을 판정하지 않는다 — 등급이 두 곳에서
다르면 사용자가 먼저 다친다.

**등급마다 보는 항목이 다르고, 항목군마다 조건도 다르다.**

| 등급 | 판정에 쓰는 항목 |
|---|---|
| 3등급 | **건강체력**(심폐지구력·근력·근지구력·유연성) **모두** + **신체조성 중 한 가지** |
| 2·1등급 | **건강체력 모두** + **운동체력**(순발력·민첩성·협응력) **중 한 가지** |


**전부 요구하지 않는 것이 요점이다.** 운동체력을 모두 요구하면 문턱이 빡빡한 항목
하나가 상위 등급을 통째로 막는다 — 성인 반응시간은 1등급 문턱이 0.301초인데 성인
`p10` 이 0.30초다. 신체조성도 같은 형태다.

**신체조성은 3등급에만 쓴다.** 기준표에서 1·2등급 행의 BMI·체지방률 칸은 비어 있다.
그리고 문턱이 아니라 **구간**이라(`18.5이상 25미만`) `body_composition_ranges.csv`
78건으로 따로 낸다 (`grade_thresholds.csv` 에 열을 더하지 않는다). `초과`/`이상` 은
경계값 한 점이라 구별하지 않는다.


**운동체력에 3등급 문턱이 없는 것은 결측이 아니다.** 3등급 판정이 그 항목을 보지
않는다는 뜻이고, 전 연령대에서 예외 없이 그렇다. 기준을 충족하지 못하면 `참가` 다.

**공단은 2025-06 개편으로 3등급 아래를 4·5·6등급으로 쪼갰다. 우리는 그 셋을 내지
않는다** — 계약(`docs/03`)의 `grade` 는 넷이고, 셋 다 "3등급 미달"이라 `참가` 로
접힌다.

## 6. 미결

| # | 항목 | 상태 | 확정 전 기본값 |
|---|---|---|---|
| ① | `044` 눈-손 협응력의 단위 | 기준표와 데이터가 불일치 | 점수 산출에서 제외 |
| ② | 궤적 곡선의 축 (요인 점수 / raw 밴드) | 미정 | raw 밴드 (`docs/03`) |
| ③ | 저표본(`n < 30`) 칸의 응답 처리 | 미정 | `score`·`percentile` 을 `null` (`docs/03`) |
| ④ | 만 7~10세 구간의 `age_group` 값 | 공식 구간에 없음. | 측정 응답은 가장 가까운 `유소년`. 측정 항목이 없어 `factors` 는 빈 배열이 된다 |
| ⑤ | 기준항목이 둘인 요인의 처리 | 미정 | 택1로 보고 더 최근 측정을 쓴다 |
| ⑦ | 어르신 연령대의 기준항목 | 이 문서 범위 밖 | 없음 — 어르신은 점수·등급을 내지 않는다. 영상 검색과 질의응답은 정상 동작한다 |
