# 03 · AI ↔ 웹서버 인터페이스 명세

AI 서비스(FastAPI)와 API 서버(Spring Boot) 사이의 호출 계약이다. 규칙과 필드를 한
문서에 둔다. 프론트는 API 서버 응답만 보고, AI 서비스를 직접 호출하지 않는다.

점수 산출은 `02` §5, 인용 근거 생성은 `04`.

**지금 필요한 것만 정한다.** 나중에 필요해질 것을 지금 정의하면 그 정의를 지키는
비용만 쓰고 얻는 것이 없다. 걷어낸 것과 그 조건은 §12에 남겼다.

---

## 1. 경계

**AI 서비스는 서비스 테이블에 쓰지 않는다.** 계산해서 JSON을 돌려줄 뿐이고,
`coach_runs`·`missions`·`coach_messages` 저장은 전부 API 서버가 한다.

| | AI 서비스 | API 서버 |
|---|---|---|
| 읽기 | `vector_store` | 전부 |
| 쓰기 | `vector_store`·`exercise_videos` 라벨 컬럼 (**오프라인 배치만**) | 전부 |
| 온라인 요청 중 DB 쓰기 | **없다** | — |

이 한 줄이 승인 게이트(§8)의 근거다. AI에 미션을 만들 경로가 없다.

**영상 메타(제목·URL·길이)는 AI가 실어 보내지 않는다.** `video_id` 만 주고 API 서버가
`exercise_videos` 에서 조인한다. 같은 데이터를 두 곳에서 보내지 않는다.

## 2. 공통

### 2.1 전송

| 항목 | 값 |
|---|---|
| 프로토콜 | HTTP/1.1, JSON (UTF-8) |
| 기준 경로 | `/v1` |
| 메서드 | `POST` (조회 1건만 `GET`) |
| 헤더 | `Content-Type: application/json` **하나뿐** |
| 인증 | 없음 — 접근 통제는 보안그룹으로 한다 |
| 망 | **내부망 전용.** 퍼블릭 ALB에 붙이지 않는다 |

`ai-service` 인바운드를 `api-server` 태스크에서만 열면 토큰이 하는 일을 네트워크가
이미 한다.

> ⚠ **`ai-service` 를 퍼블릭에 노출하는 순간 이 결정은 무효다.** 그때는 토큰을 먼저
> 넣고 노출한다. 순서를 바꾸지 않는다.

### 2.2 오류

성공은 payload를 그대로 돌려준다. 봉투를 씌우지 않는다. 실패는 한 형태다.

```json
{"error": {"code": "RUN_IN_PROGRESS", "message": "실행 중인 코치 실행이 있습니다"}}
```

`error.message` 는 개발자용이다. **화면에 그대로 노출하지 않는다.**

| 코드 | `error.code` | 발생 조건 | 호출자 처리 |
|---|---|---|---|
| `200` | — | 정상 (거부 응답 포함) | — |
| `202` | — | 비동기 실행 접수 | 폴링 시작 |
| `400` | `BAD_REQUEST` | 필수 필드 누락, 타입 불일치 | **호출자 버그.** 화면에 띄우지 말고 로그 |
| `400` | `ITEM_NOT_ALLOWED` | 측정 항목 `005`·`006`(혈압) 전송 | 위와 같다 |
| `404` | `RUN_NOT_FOUND` | `run_id` 없음 | — |
| `409` | `RUN_IN_PROGRESS` | 같은 프로필에 실행 중인 run 존재 | 기존 `run_id` 조회 |
| `503` | `TEMPORARILY_UNAVAILABLE` | LLM·인덱스 일시 장애 | §2.3의 엔드포인트별 재시도 |

**거부(`refused: true`)는 오류가 아니다.** 자료에 없어 답하지 못하는 것은 정상 동작이며
HTTP `200` 이다. 재시도하지 않고, 예외로 던지지 않는다 — 예외로 만들면 거부가 오류
로그에 섞여 거부율을 측정할 수 없다.

### 2.3 재시도·타임아웃

| 엔드포인트 | 타임아웃 | 재시도 |
|---|---|---|
| `/fitness/assessment` · `/fitness/trajectory` | 3s | 2회 (지수 백오프, 멱등) |
| `/videos/search` | 4s | 2회 |
| `/coach/messages` | 10s | **0회** — 사용자 질문은 중복 과금이다 |
| `POST /coach/runs` | 2s | **0회** — 중복은 `409` 로 막는다 |
| `GET /coach/runs/{run_id}` | 3s | 1.5s 간격, 최대 40회 |

### 2.4 공통 타입

| 이름 | 타입 | 허용값 |
|---|---|---|
| `ProfileRef` | string | 불투명 참조. 이름·생년월일·연락처를 담지 않는다 |
| `Sex` | string | `M` · `F` |
| `AgeUnit` | string | `세` · `개월` — **유아기만 `개월`** |
| `AgeGroup` | string | `유아기` · `유소년` · `청소년` · `성인` · `어르신` |
| `InputLevel` | string | `L0`(나이·성별) · `L1`(+신장·체중) · `L2`(+측정값) |
| `FitnessFactor` | string | `심폐지구력` · `근력` · `근지구력` · `유연성` · `민첩성` · `순발력` · `협응력` · `평형성` |
| `Band` | string \| null | `strength`(백분위≥75) · `steady`(25~75) · `growth`(<25) · `null`(측정값 없음) |
| `ItemCode` | string | 측정 항목 3자리 코드. §9 |
| `Role` | string | `주행자` · `동반자` · `응원` |
| `Date` | string | `YYYY-MM-DD` |

**아이 프로필은 `유아기`·`유소년`·`청소년` 셋이다.** 연령 안전 규칙은 이 셋에 적용된다.

**`factors` 가 빈 배열로 오는 것은 오류가 아니다.** 만 7~10세(측정 0건, `02` §2.2)와
어르신(기준항목 미정, `02` §6 ⑦)이 여기 해당한다. 두 구간 모두 `videos/search` 와
`coach/messages` 는 정상 동작한다. `평형성` 도 같은 이유로 현재 산출되지 않는다.

### 2.5 보내지 않는 것

- 이름·생년월일·연락처·계정 식별자. 프로필은 `profile_ref` 로만
- 측정 항목 `005`·`006`(혈압) — 값이 있어도 보내지 않는다. AI는 이 항목을 다루지 않는다

### 2.6 문구와 노출 범위

응답에는 **코드 값**(`band`·`factor`)과 **표시 문구**(`copy`)가 나뉘어 온다. 코드
값을 화면에 그대로 쓰지 않고, 표시 문구는 고쳐 쓰지 않는다.

응답은 `child_scope` 와 `parent_scope` 로 갈라 온다. **`child_scope` 에는 백분위·
점수·체중이 들어 있지 않다** — 아이 화면이 실수로 노출할 값이 애초에 없다.

**"부족"·"미달"·"하위"를 쓰지 않는다.**

## 3. `POST /v1/fitness/assessment`

**용도** — 한 사람의 측정값을 또래 분포·등급 기준과 대조해 요인별 점수와 등급 카드로
바꾼다. 미션 편성과 궤적 조회가 이 결과를 전제로 한다.

**호출 시점** — 프로필 생성이나 측정값 저장·수정 직후 **1회**. 결과를 저장해 두고 화면
진입마다 다시 부르지 않는다. **측정값이 없어도 `200`** 이다.

**측정값은 선택 입력이다.** 대부분의 사용자는 `L1` 에 머문다. `L2` 를 전제로 화면을
설계하면 대부분에게 빈 화면이 나온다.

| `input_level` | 입력 | `child_scope` | `parent_scope.factors` |
|---|---|---|---|
| `L0` | 나이·성별 | 연령대 일반 제안 | 빈 배열 + `peer_distribution` |
| `L1` | + 신장·체중 | 연령 기반 제안 | 빈 배열 |
| `L2` | + 측정값 일부 | 최저 요인 1개 | 측정된 항목만 |

### 3.1 요청

| 필드 | 타입 | 필수 | 제약 · 설명 |
|---|---|---|---|
| `profile_ref` | string | ● | `ProfileRef` |
| `age` | integer | ● | `age_unit` 기준. 유아기는 개월 수 |
| `age_unit` | string | ● | `AgeUnit` |
| `sex` | string | ● | `Sex` |
| `height_cm` | number \| null | ○ | 30.0 ~ 230.0 |
| `weight_kg` | number \| null | ○ | 5.0 ~ 250.0 |
| `measurements` | object | ○ | `{ItemCode: number}`. 기본값 `{}`. **`005`·`006` 포함 시 400** |

```json
{
  "profile_ref": "p_c7a91f",
  "age": 11, "age_unit": "세", "sex": "F",
  "height_cm": 148.0, "weight_kg": 41.0,
  "measurements": {"028": 41.3, "012": 4.0, "020": 70, "022": 133}
}
```

`measurements` 키는 **코드 3자리**다. 이름을 키로 쓰지 않는 이유는 표기가 흔들리기
때문이다 — 기준표는 `제자리멀리뛰기`, 컬럼정의서는 `제자리 멀리뛰기` 다.
**코드가 식별자이고 이름은 표기다.**

| `child_scope` | object | ● | §3.3 |
| `parent_scope` | object | ● | §3.4 |
| `low_sample` | boolean | ● | 해당 연령·성별 표본이 30 미만 |
| `disclaimer` | string | ● | 상시 노출 문구. 그대로 표시한다 |

### 3.3 `child_scope`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `focus_one` | object \| null | ● | 이번 주기에 제안할 요인 **하나**. 요인 간 비교·순위를 담지 않는다 |
| `focus_one.factor` | string | ● | `FitnessFactor` |
| `focus_one.copy` | string | ● | 아이 화면 문구. **고쳐 쓰지 않는다** |

### 3.4 `parent_scope`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `grade` | string \| null | ● | `1등급`·`2등급`·`3등급`·`참가`. L2가 아니면 `null` |
| `peer_distribution` | array | ● | 같은 연령대·성별의 등급 비율 `{grade, ratio}` |
| `factors` | array | ● | §3.5. L2가 아니면 빈 배열 |
| `copy` | object | ● | `strength`·`focus` 키. 부모 화면 문구 |

### 3.5 `parent_scope.factors[]`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `factor` | string | ● | `FitnessFactor` |
| `item_code` | string | ● | `ItemCode` |
| `item_name` | string | ● | 데이터 항목명 (`왕복오래달리기`) |
| `item_label` | string | ● | **그 연령대의 실제 시험명** (`15m 왕복 오래달리기`) |
| `unit` | string | ● | `%` · `cm` · `회` · `초` 등 |
| `value` | number \| null | ● | 측정값. 미측정이면 `null` |
| `score` | number \| null | ● | **0~100.** 미측정·표본부족이면 `null` — **0점이 아니다** |
| `percentile` | integer \| null | ● | 0~100. 참고값이며 척도가 아니다 |
| `band` | string \| null | ● | `Band` |
| `n` | integer | ● | 그 칸의 표본 수 |

| `band` | 사용자 문구 |
|---|---|
| `strength` | "잘하고 있는 영역" |
| `steady` | "꾸준히 하고 있는 영역" |
| `growth` | "지금 키우기 좋은 영역" |
| `null` | 표시하지 않는다 |

**`item_label` 이 별도인 이유** — 같은 코드 `020` 이 유소년은 15m, 청소년·성인은 20m
왕복 오래달리기다. `item_name` 만 쓰면 부모가 작년 기록과 비교하다 틀린다.

`n < 30` 이면 `percentile` 과 `score` 를 `null` 로 내리고 `low_sample: true` 를 단다.
**이 처리는 확정이 아니다** — 선형 보간으로 점수를 내는 안과 갈려 있다 (`02` §6 ③).

## 4. `POST /v1/videos/search`

**용도** — 처방 운동명이나 체력 요인으로 공단 운동영상을 찾아 **근거와 함께** 돌려준다.

**호출 시점** — 사용자가 영상을 직접 검색하거나 미션 상세에서 "이 동작 영상 보기"를
누를 때. **미션 편성 중의 영상 선택은 이 API를 거치지 않는다** — `/coach/runs` 내부
`retrieve` 단계가 같은 검색을 수행한다.

### 4.1 요청

| 필드 | 타입 | 필수 | 제약 · 설명 |
|---|---|---|---|
| `age_group` | string | ● | `AgeGroup`. **필수다** |
| `fitness_factors` | array\<string\> | ○ | `FitnessFactor`. 0~3개 |
| `exercise_names` | array\<string\> | ○ | 운동처방 어휘 638개 중에서만. 어휘 밖 문자열은 무시된다 |
| `k` | integer | ○ | 1~10. 기본값 5 |

`fitness_factors` 와 `exercise_names` 중 **최소 하나**는 있어야 한다.

**`age_group` 이 필수인 것은 정확성이 아니라 안전 때문이다.** 아이 질의에 성인 처방이
섞이면 위험하다. 필터는 애플리케이션이 아니라 검색 질의 자체에 얹어, 거치지 않는
경로가 없게 한다 (`04` §3).

**공간·소음·기구·길이 필터는 받지 않는다.** 라벨이 그 필드를 갖지 않아 거를 데이터가
없다. 요청에 넣으면 무시가 아니라 `400` 이다 — 못 거는 조건을 받는 것보다 정직하다.

```json
{
  "age_group": "유소년",
  "fitness_factors": ["유연성"],
  "exercise_names": ["다리 벌려 앞으로 상체 숙이기", "전신 루틴 스트레칭"],
  "k": 5
}
```

### 4.2 응답 `200`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `hits` | array | ● | 최대 `k`개. **0건일 수 있다** |
| `filtered_out.age_group` | integer | ● | 연령 필터에서 제외된 편수 |
| `filtered_out.below_threshold` | integer | ● | 유사도 임계 미달 편수 |

`hits[]`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `video_id` | string | ● | YouTube video id. 제목·URL·길이는 API 서버가 조인한다 |
| `start_sec` | integer \| null | ● | 해당 동작이 시작되는 지점 |
| `score` | number | ● | 0.0~1.0 유사도. **§3.5의 요인 점수(0~100)와 다른 값이다** |

## 5. `POST /v1/coach/runs` · `GET /v1/coach/runs/{run_id}`

**용도** — 가족 구성원의 측정 상태를 보고 한 주 분량의 미션을 편성해 **제안**한다.
저장도 실행도 하지 않으며, 보호자가 승인해야 미션이 된다.

**호출 시점** — "이번 주 미션 받기". 프로필당 주 1회이며 동시 실행은 `409` 로 막힌다.
버튼을 두 번 눌러 제안이 두 개 생기면 어느 것을 승인했는지가 흐려진다. 내부 4단계에

## 8. 승인 게이트와 저장

```
① AI가 제안 반환          → DB에 쓰지 않는다
② API 서버가 coach_runs 저장 (approved_at = NULL)
③ 보호자 승인             → approved_at 기록
④ 같은 트랜잭션에서 missions INSERT ← proposal.missions[] 복사
```

**API 서버가 보장할 것**

- `approved_at IS NULL` 이면 그 run의 `missions` 는 0건
- `missions` INSERT는 승인 트랜잭션 안에서만 — 코드 경로 하나
- 아이 계정은 승인 주체가 될 수 없다

**AI가 보장할 것** — `missions` 쓰기 경로가 존재하지 않는다. 승인 이전에 부작용 있는
도구가 호출되지 않는다. 모든 제안에 근거 인용이 남는다.

거부되면 `rejected_at` 을 적고 끝이다. **재제안은 새 run이다.**

**승인 시 API 서버가 채우는 것은 소유권 컬럼(`id`·`user_id`·`coach_run_id`·
`created_at`)뿐이다.** 그 외 어떤 필드도 승인 시점에 새로 만들지 않는다 — 새로 만들면
승인된 것과 제안된 것이 갈라지고, 인용이 어느 판정에 붙은 것인지 알 수 없게 된다.
이 컬럼 목록은 §11 ① 확정 전의 잠정안이다.

| 응답 필드 | 저장 위치 |
|---|---|
| `run_id` · `steps` · `proposal` | `coach_runs.*` (JSONB 그대로) |
| `proposal.missions[]` | 승인 시 `missions` 각 행 |
| `proposal.citations` | `missions` 의 근거 컬럼 (컬럼명 §11 ①) |
| `answer`·`citations`·`refused` | `coach_messages.*` |

**AI 응답을 가공하지 않는다.** 컬럼으로 펼치면 제안과 저장본이 갈라진다.
**거부 응답도 저장한다** — 거부율이 품질 지표다.

## 10. 호출자 체크리스트

**API 서버**

- [ ] `coach_runs.approved_at` 이 `NULL` 이면 그 run의 `missions` 는 0건
- [ ] `missions` INSERT는 승인 트랜잭션 안 **한 경로**에서만
- [ ] `proposal` 을 JSONB 그대로 저장 (컬럼으로 펼치지 않는다)
- [ ] 거부 응답을 재시도하지 않고 저장한다
- [ ] `400` 을 화면에 노출하지 않는다
- [ ] 혈압 항목을 전송하지 않는다

**프론트**

- [ ] 아이 화면에서 `parent_scope` 를 읽지 않는다
- [ ] `citations` 를 화면에서 생략하지 않는다
- [ ] `answer` 를 편집하지 않는다
- [ ] `video: null` 인 세션을 렌더링한다
- [ ] `factors[].score` 가 `null` 이면 0점이 아니라 **미산출**로 표시한다
- [ ] `disclaimer` · `notice` 를 그대로 노출한다

`bands` 축(§7.2), 만 7~10세 `age_group`·어르신 기준항목(§2.4),
`below_threshold` 임계값(§4.2).

## 12. 지금 넣지 않은 것

**없어서 못 넣은 것이 아니라 지금은 넣지 않기로 한 것이다.**

| 뺀 것 | 넣어야 하는 시점 |
|---|---|
| 인증 헤더 (서비스 토큰) | 퍼블릭 노출 때. **노출보다 먼저** |
| `X-Request-Id` | 장애 추적이 실제로 안 될 때 |
| 계약 버전 협상 헤더 | 깨는 변경이 처음 생길 때. 경로에 이미 `/v1` 이 있다 |
| `meta` 봉투 (`latency_ms`·`model_version`) | 운영 대시보드를 만들 때 |
| 멱등성 키 | 409만으로 중복이 안 막힐 때 |
| `proposal_hash` · `expires_at` | 사용자가 제안을 편집한 뒤 승인하는 기능이 생길 때 |
| DB 계정 분리·컬럼 GRANT | 경계가 코드 검토만으로 못 미더워질 때 |
| 공간·소음·기구 필터 | 라벨 스키마가 그 필드를 라벨할 때 |
| 최근 수행 이력 입력 | 재추천이 같은 운동을 반복할 때 |
| 캐시 키·TTL 규약 | 호출량이 문제가 될 때 |

**필드 추가는 계약 버전을 올리지 않는다. 필드 삭제·의미 변경은 올리고 양쪽이 함께
배포한다.**
